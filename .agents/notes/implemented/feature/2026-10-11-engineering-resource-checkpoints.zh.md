# Agent Note: 工程资源检查点

Status: implemented

[English](2026-10-11-engineering-resource-checkpoints.md) | 中文

## 问题

传入项目复制限额和原生受管日志配额不包括后续项目输出及官方 Session 存储。把任一限额当作完整动作或内存上限，会产生错误的容量和效率结论。副本在成功、拒绝及中断运行后仍保留，也可能属于另一 Host 中的运行。

## 决策

[工程资源 owner](../../../../apps/desktop-host/src/experiments/engineering-resources.ts)消费独立于请求／输出限额的显式本机用户检查点限额。准入保留每个分配的完整副本费用，不返还未用空间，因而另一 Host 的部分或在途副本不会被当成免费。独立发布的物理分配身份区分实际空分配和未计量历史路径。旧日志仍可读取，不回填过去的 ownership；新准入拒绝未知 owner。

owner 在操作之间及排空后观察整个复制树。官方持久观察提供逻辑前缀，官方 `stat` 在代次保护内提供物理文件长度。owner 保留缺失观察，磁盘／内存峰值为 null，因为检查点发生在分配后及写入之间。动作执行后的拒绝阻止后续工作，同时保留实际工具结果和因果 T11 回执。独立 sidecar 保留旧工程／Session 格式，不改变原生受管类别。

## 考虑过的替代方案

**复用传入闭包或受管日志限额。** 这些 owner 不观察后续副本输出或官方 Session 文件，复用其计数无法约束或认证这些资源。

**只计入当前保留长度。** 另一 Host 中的未完成分配可能在扫描后增长。保留完整显式上限使协作准入保持保守，不从缺失终态或时间推断排空。

**已执行动作资源超额后抛错。** 工具流水线会把真实结果替换为错误，丢失原因果回执链接。撤销后续工作能保留两项事实：动作已执行，而资源准入不再允许继续。

## 后果

即使当前文件很小，容量也可能在二十日志保留限额之前拒绝；保留分配不自动裁剪或接纳。动作期间磁盘增长、副本外 Shell spill、分配开销及解码／Host 内存仍在检查点保证之外。完整峰值约束需要实际 writer 或执行提供方拥有该限额，扫描方不能提供它。

支持 profile 测试保留合成超额输出，验证 Session 预算拒绝后零分派，并验证输出拒绝后保留实际 T11 回执。冷读、历史 sidecar 缺失、伪造峰值及不分配副本的总容量拒绝分别检查。renderer 资格使用已有物理 Electron runtime、生产 Main／preload 和隔离合成 profile，不提供安装、真实模型质量、提供方缓存或计费资格。用户限额和失败行为归[owner 参考](../../../../apps/desktop-host/src/experiments/README.zh.md#isolated-engineering-task)所有。
