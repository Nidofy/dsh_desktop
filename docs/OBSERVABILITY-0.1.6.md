# 0.1.6：会话诊断与紧凑工具输出实验

本轮落实快速迭代方案的第一版，保留官方 DSH **0.1.5-rc.2**。不修改上游源码，不增加模型工具或提示词，不改变请求调度。后续的运行对比器、并发实验和求解器 hg 兼容没有混入本轮。

## 使用

Help → **会话诊断 / Session Diagnostics**，或设置页“打开会话诊断 / 工具输出实验”。诊断独立窗口复用 DSH 同源 cookie；可选择会话、查看请求详情、导出 JSON/Markdown。

轻量采集默认开启，可实时关闭并跨重启保留设置。关闭不会取消正在运行的任务，也不会自动清除已有记录；“清空当前记录”单独执行。记录只驻留内存，引擎重启后清空；需要保留时先导出。

首次未显式选择实验时保留原生设置，标准预算为 50,000 bytes。选择紧凑模式后预算为 24,000 bytes；保存后待任务结束，再通过 Help → Restart Engine 应用。切回原生模式恢复 50,000 bytes。该功能调用原生 spill-policy：完整格式化结果仍保存，部分工具内联结果缩为带读取位置的预览；`read` 等原生豁免保持不变。不会立即中断任务，不宣称能减少所有工具输出或必然提升缓存。

两个开关独立。只开关采集不会覆盖工具预算。存在用户自定义原生预算时，页面“当前工具预算”显示启动时的实际值；只有显式切换工具实验才由 Desktop 接管这一项。运行中直接在原生高级设置修改 spill-policy 后，应重启使诊断配置快照更新。

诊断密钥由 Windows Credential Manager 保存，经私有启动管道传入 Node。设置页可重置密钥，下次重启生效。无法访问凭据时使用临时密钥，页面明确提示；正常聊天不因此失败。

## 采用的附件建议

- P0 观测与 EXP 紧凑输出分离：相同包内独立控制、独立验证，不改变默认预算。
- 附带 [指纹规范](FINGERPRINT_SCHEMA.md)，保持数组顺序与原文字符串；对象规范化与工具序列化顺序分开。
- 分类只输出本地事实，不提供“缓存失效原因”或“逐出风险”评分。
- 功能验证直接覆盖最终 HTTP body 和轻量开销，不等待大型回归或内网新反馈。

## 验证与边界

- `tests/observability.mjs`：原流对象透传、取消、异常、诊断失败隔离、存储上限、原文不导出、指纹规则、持久化、原生 spill 全文保留与预算恢复。
- `tests/observability-wire.mjs`：两种真实 DSH adapter → 本地 mock；连续两轮、原生 read 工具循环、usage、错误/取消、鉴权与跨源拒绝、导出脱敏、开关持久化、稳定 scope 和预算恢复。采集 ON/OFF 的最终 JSON 及原始 HTTP body 逐字节相同。测试只记录合成任务，不记录 Authorization。
- 现有设置同步和多模型协议回归通过；Windows 凭据/进程等 9 个 Rust release 测试通过，含诊断密钥复用与重置。
- [微基准](evidence/observability-benchmark-0.1.6.json)：300 个逻辑请求，每个 20 条 2,048 字符消息、4 个工具、16 个流块。无网络等待，OFF 约 1.05–1.09 ms，ON 约 54.7–55.9 ms；ON CPU 47–79 ms，记录约 0.81 MB。Node 进程峰值 RSS 约 42.8 MiB（OFF）和 51.1–51.5 MiB（ON）；独立进程/GC/计时粒度影响这些数字，不用百分比推断真实任务性能。

逻辑诊断看不到最终 HTTP 请求、服务端缓存 key、prefill 或逐出行为；缺少 usage 时不猜原因。统计包含当前保留窗口，不能当作全部历史或当前上下文占用。原生整会话统计单独呈现。

错误状态可靠保留，但 adapter 可能不保留 HTTP status；没有该字段时不从报错文本猜测。初次/超大上下文的指纹不完整会显示不可比，聊天照常继续。

候选版用于继续内网实际体验。合成测试不证明真实网关效果，也不替代 Windows 10/干净企业镜像验收。

本机独立测试配置启动 0.1.6 桌面成功，4,345 ms 就绪。诊断页面已用合成数据在浏览器检查：表格、会话筛选、原生时间统计、请求详情和实验待重启提示正常。原生窗口自动化授权未得到响应，因此不将 Help 菜单点击、原生窗口中的下载保存交互记为已验证；相关后端鉴权和导出 HTTP 响应已由集成测试验证。
