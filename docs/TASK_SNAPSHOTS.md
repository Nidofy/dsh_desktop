# 文件快照与安全恢复（0.2.0 开发中）

入口：Help → Settings & Diagnostics → 文件快照与恢复。支持手动快照，以及用户为指定工作区启用的每轮自动快照；原来的变更比较基线仍单独工作，不将其冒充完整备份。

## 每轮自动快照

1. 载入当前连接快照，在「设置文件范围 / 新建快照」填写工作区和明确的相对文件路径。
2. 点击「为此工作区启用 / 更新自动快照」。默认关闭，每连接最多 16 个工作区，仅匹配会话的同一工作区，不递归启用其他工作区。
3. 后续主任务每轮通过 DSH 正式 pre-step 等待链完成采集与开始确认，之后才进入首个模型/工具步骤。原生 turn/end 触发一次结束封存；同工作区紧接着开始的下一轮等待前一轮的封存请求结束。
4. 回到设置页载入快照，查看最近自动结果、会话和轮次，按既有预览/冲突检查恢复。停用工作区不删除备份；尚未确认开始的请求可因停用而拒绝，已确认开始的任务仍按原文件范围封存。

开始/结束请求各有约 14 秒等待预算，超时或失败后任务继续，不重试、不补采、不自动恢复。未完整确认的记录保留并标出；缺少结束记录时不能恢复。现有 20 份 / 256 MiB 配额仍然生效，达到上限必须自行归档/清理，不会静默删除旧备份。多个会话或外部编辑器可以同时修改工程，快照只说明任务期间所选文件的状态，不代表 Agent 独占修改或全仓库原子备份。

自动通道仅使用桌面 supervisor 与 Node 子进程继承的私有 stdin/stdout 管道，每次启动生成随机令牌和引擎身份。不新增 HTTP 控制入口、模型工具、环境凭据或提示内容；模型请求不包含该令牌。常规本机文件管理和恢复仍仅由 Settings Tauri IPC 发起。范围配置单独保存为 `DSH_HOME/desktop-snapshot-scopes.json`，有修订冲突检查，不随日志清理删除。

## 使用流程与覆盖范围

可以在设置页「浏览工作区并选择文件」浏览上方工作区的直接子项，进入目录后逐文件勾选，再点击「将勾选文件加入范围」。已有手填路径保留并去重，不会递归加入整个目录，也不会自动启用快照。每次最多展示 300 项、扫描 2000 项，超出时明确提示；仍可直接填写路径。修改工作区会清空旧列表，链接和 Git/Hg 元数据不列出，超过 8 MiB 的文件不可勾选。保存范围或采集时还会复核类型、大小及文件身份。

1. 载入当前连接快照，输入本机绝对工作区路径，以及每行一个的相对文件路径。
2. 在任务开始写入前保存开始快照。保存原始字节，支持文本与二进制；已有人工修改也原样保存。
3. 在任务结束、工程停止写入后，固定一次结束状态。之后不能重新固定以绕过冲突检查。
4. 刷新恢复预览，逐文件选择后恢复。冲突、不可检查和已经执行过的条目不能勾选。

范围为 1–128 个明确指定的文件，每个 8 MiB、合计 32 MiB；开始与结束均受限。可以预先列出尚不存在的文件，但父目录必须已存在。恢复这些路径时，原来存在的文件恢复原始字节，原来不存在而结束时存在的文件会被删除，界面明确显示该操作。未列入范围的文件不会被修改或删除，也不会自动增加覆盖范围。

这不是全仓库快照，也不是文件系统级原子快照。采集会重新核对每个文件，但使用者仍应暂停任务、构建器和编辑器的写入。没有把任务期间变化归因为 Agent 独占修改。

## 文件处理约束

- 仅本机固定磁盘；需要文件系统支持 Windows 文件身份与数据流查询。目录或文件重解析点、符号链接、junction、硬链接、EFS 加密和离线文件均不接受。暂不支持网络盘。
- 只备份普通文件的默认数据流。存在命名数据流时拒绝，避免恢复删除文件时丢失其额外内容。不是 ACL、时间戳、压缩属性等完整元数据备份。
- 不操作 `.git` / `.hg` 元数据、Git 暂存区、commit、branch 或 Hg dirstate。相对路径校验之外，还按已打开句柄的实际路径检查元数据目录，防止短文件名别名绕过。
- 开始内容独立保存在连接 home 下，即使任务提交或改变 VCS 历史，也不依赖原来的 commit/blob 才能恢复。

## 恢复契约

1. 校验保存内容的 SHA-256 与长度，核对工作区目录身份。
2. 从磁盘根开始固定每一级父目录句柄，拒绝重解析点，持有期间不允许目录删除或重命名。
3. 已存在文件通过独占句柄打开，拒绝并发读写/删除。使用同一个句柄核对结束时的内容 hash、文件身份、长度和修改时间，校验与写入之间不重新打开路径。
4. 在修改任何工作区字节之前，将当前内容和恢复准备记录写入快照目录并同步到磁盘。
5. 原地写入已有文件并验证内容；恢复缺失文件使用 `CREATE_NEW`，不会覆盖检查后突然出现的文件；删除仅针对已经锁定且匹配结束记录的文件句柄。
6. 写入失败时，已有文件尝试恢复操作前字节，并记录 `ROLLED_BACK` 或 `INTERRUPTED`。发生进程退出、部分写入或结果记录缺失时，保留备份，之后不自动重放。

多个文件不是一个事务。后续文件冲突或失败时，前面已经恢复的文件保持结果，界面要求刷新确认；不声称整批全成或全败。突然断电、磁盘故障也不能保证恢复原地写入的完整性，因此始终保留独立的恢复前内容。

Windows API 契约参考：[CreateFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew)、[SetFileInformationByHandle](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfileinformationbyhandle)。具体可用性以本机测试和目标机验收为准。

## 存储、身份与权限

每个连接分别保存在 `DSH_HOME/desktop-task-snapshots/<编号>/`，设置页展示实际存储路径。手动快照使用随机编号；任务接口按会话与轮次生成固定编号，避免重启后重复采集同一轮。

| 文件 | 含义 |
| --- | --- |
| `start.json` | 指定路径、开始状态、工作区身份 |
| `before-N.bin` | 第 N 个文件的开始原始内容（从 0 起算） |
| `end.json` | 一次性固定的结束状态 |
| `pre-restore-N.bin` | 恢复操作之前的原始内容 |
| `restore-N.json` | 已持久化的恢复准备记录与预期 hash |
| `result-N.json` | 本次操作结果；不存在时结果未确认 |
| `task-intent.json` | 任务采集意图：会话、轮次、引擎实例、请求身份、期限和指定范围；开始读文件前保存 |
| `confirmed.json` | 任务开始确认；未确认的内容备份不能用于任务恢复 |
| `end-intent.json` | 一次性结束采集意图；失败后不在更晚时刻补采 |

这些文件可能含工程源码，保留在当前连接本机目录，不上传、不给模型注入上下文。不要只拷贝 manifest 后删除 `.bin` 文件。需要人工恢复时先保留整个快照目录，再根据路径与 hash 核对两份内容；不要直接对未核对的工程批量覆盖。

每连接最多 20 份 / 256 MiB。采集与恢复在写入前保守预留容量；达到上限时拒绝新操作，不自动清理恢复前备份。失败的部分采集保留占用并在界面标出数量。可先导出归档，再在设置页「本机存储管理」单独启用并选择备份目录进行永久清理，见 [存储管理](STORAGE_MANAGEMENT.md)。导出不会联动删除。

## 归档、校验与导回

在「归档 / 校验 / 导回快照」中，选择一份已有快照，填写工程和快照库之外的已有本机目录，点击导出。每次创建独立的 `DSH-snapshot-<编号>-<随机编号>` 子目录，复制原始内容、开始/结束记录及已有恢复前备份和回执，最后写入 `archive-manifest.json` 并重新校验。目录形式便于直接保留与检查，不依赖额外压缩工具；不是产品离线安装包。

清单记录格式版本、快照编号、导出时间，以及每个文件的名称、长度和 SHA-256。再次校验会核对完整文件集合，缺失、额外、修改、链接、命名数据流或超限均拒绝。原始内容也必须符合开始记录中的 hash。SHA-256 是完整性校验，不是数字签名或加密；归档包含源码与原工作区路径。

「导回当前连接快照库」先验证归档，随后以原编号创建快照，开始记录最后写入。同编号或此前失败的部分导入已存在时拒绝覆盖，仍受 20 份 / 256 MiB 配额限制。导入不修改工作区，不重新采集，也不会把未确认状态变成可恢复状态；已有恢复回执保留，防止重放。之后仍需明确选择、预览并恢复；原工作区路径与目录/文件身份等检查继续生效，不提供自动迁移到其他工程或其他电脑的恢复。

失败导出/导入保留部分文件且不自动重试、删除或回滚；不完整导出没有有效清单。缺少完整开始记录或原始备份已经损坏的残留不能通过此入口导出，可保留原存储目录供人工检查。原生 Tauri 窗口和真实磁盘故障仍待目标机验收。

手动采集、恢复与范围设置仅通过打包的本地 Settings 窗口 Tauri 命令，远程 DSH/诊断页面没有这个 IPC 权限。请求绑定用户载入时的连接身份，连接变化后拒绝；与保存/切换连接共用串行锁。自动流程只读取用户启用的范围，不写工程文件。恢复是用户主动的桌面文件管理操作，不作为模型工具，也不使 Agent 获得越过 DSH sandbox 的新执行路径。

## 验证和仍需完成的内容

### 任务生命周期存储与通道

原生存储层提供 `capture_task`、`confirm_task`、`seal_task`，由 supervisor 检查用户启用范围后调用。这些任务事件接口没有加入 Settings 请求枚举，也没有开放给远程页面或模型工具；Settings 只增加列出、启用/更新、停用范围的操作。

- 先持久化采集意图，再读指定文件；同一会话/轮次的失败或部分采集保留，不自动重试。请求身份、工作区或范围变化时拒绝复用。
- 成功采集不等于任务已确认开始。确认时重新核对所选文件；开始采集和首次确认均要求有效的 15 秒内请求期限。重复确认仅返回原确认，不重新采集。
- 只有相同引擎实例和请求身份能确认、封存；重启后的引擎不能冒充原轮次补采。结束意图只写一次，失败后保留未确认状态；重复成功封存返回原结果。
- 任务快照在开始/结束身份和确认记录校验通过后，才进入既有的冲突检查和恢复前备份流程。Settings 显示会话、轮次及未确认边界，禁用任务快照的手动封存。
- 私有管道按请求编号确认，过期回执不能恢复已超时请求。取消或回执失败时放弃本引擎中的活动关联；即便原始内容已保存，也不据此补采结束状态。连接切换与恢复操作占用原生操作锁时，自动采集拒绝而不是与引擎停止相互等待。

原生 Rust 测试覆盖：已有修改/二进制/新增/删除回环；Git/Hg 元数据保持不变；预览后再编辑、同内容更换文件身份；文件占用和父目录重命名；硬链接、junction、命名数据流；坏备份、工作区替换；大小和数量上限；连接隔离；模拟中断冷读不重放；注入部分写入失败时的回滚和新建失败。

浏览器 fixture 验证设置页的手动采集、固定结束状态、冲突禁用、逐文件选择和已恢复禁用，沿用现有 DSH 主题。它不代表真实 Tauri 窗口点击已经验收，也不代表实际断电/磁盘故障测试已完成。

新增验证：原生范围修订、停用与引擎身份；私有管道取消/晚到回执、重复工具步和跨轮封存等待；真实捆绑 DSH OpenAI/Anthropic 各两轮任务，首个模型请求之前确认原生备份，第二轮之前封存第一轮，以及从真实第二轮快照恢复文件。测试使用隔离工程与合成模型响应，不代表已验收原生 Tauri 点击或全部桌面 supervisor 故障时序。

新增归档验证：二进制/已有修改/新文件导出、导回与恢复；保留恢复前备份和回执；同编号不覆盖；坏原件、额外/缺失/被修改文件及硬链接拒绝；未确认任务归档后仍不可恢复。浏览器 fixture 验证目录勾选、范围追加、导出回执、校验失败提示、重复导入拒绝与独立导回。它不代替真实 Tauri 桥验证。

## 从变更面板定位与查看恢复记录

变更页选择任务轮次基线后，可请求桌面设置定位同一会话/轮次的文件快照。手动基线不具备任务关联；比较基线与文件快照分别启用，没有原始备份时不会从差异补造快照。入口通过受同源检查的 POST 和现有私有管道发送有期限的定位请求；原生再次检查任务快照存在，之后只显示设置窗口，不新增模型工具、文件恢复 API 或模型请求。

设置页显示「载入来自变更面板的任务快照」，用户点击后读取记录，保留手填的文件范围。连接已切换、快照已归档或记录不可读时拒绝；不会重放定位失败的请求。恢复仍需单独预览并选择文件。

「查看备份与恢复记录」可显示每个文件的开始/结束大小与 SHA-256、原始备份/恢复前备份校验结果，以及恢复准备和结果记录时间。该接口不访问工程，所以原工作区移走或丢失时仍可查看。缺失或不匹配的日志、无法确认的结果显示未知；损坏备份显示未验证，不伪装成成功。历史“已恢复”只描述保存的回执，不能证明当前工程内容未再改变。

新增原生测试覆盖历史回执与当前内容分离、工作区移走仍可查看、伪造孤立回执不升级成功、备份损坏、过期导航与手动快照拒绝。真实 DSH 两协议验证任务基线 → 原生管道 → 对应快照编号，拒绝手动基线和跨来源请求，导航不增加模型调用或写工程。浏览器 fixture 验证详情、未知状态、手动基线禁用和深浅色字号；原生窗口实际显示/聚焦尚未验收。

后续：真实 Git/Hg 大工程、完整原生桌面与中断现场验收。当前版本仍是开发构建，未标记 stable。
