# 桌宠运行中启停验收

`desktop-process-smoke.ps1` 与 `desktop-pet-window.ps1` 会在启动前写入启用状态，只能验证冷启动。发布桌宠窗口或设置命令的修改时，必须补充以下实际 Windows 操作，不能用预设配置启动代替。

使用完整候选程序目录及独立 `LOCALAPPDATA`；退出已有 DSH 后启动，避免单实例锁令测试程序直接结束。使用正常非管理员账户。不要把真实连接密钥或会话复制进测试目录。

1. 从默认关闭的桌宠状态进入设置 → 桌面宠物，勾选启用。记录设置命令完成、生产图集解码、透明宠物画面以及主窗口仍可操作。
2. 连续添加至 3 只，核对 3 个实际窗口及上限按钮状态。
3. 关闭总开关，确认全部宠物窗口消失。再次开启，确认 3 只均恢复。
4. 切换实例，关闭/重新启用当前实例，确认不影响其他实例。
5. 检查设置页控件文字、复选框同排、分组折叠以及窗口变窄后的排列；分别记录实际检查的主题和缩放。
6. 宠物打开时点击运行状态 → 退出。检查桌面程序及其后台引擎、WebView 子进程都结束；单纯关闭窗口到托盘不能算退出通过。
7. 重新启动同一隔离配置，确认实例恢复；退出后再次检查无残留进程。
8. 将现场使用的 EXE SHA256 与包中构建记录匹配，保存日志、画面、窗口数量和进程清理证据。

原生功能、素材检查、浏览器布局检查和硬件现场检查分别记录，不能互相替代。测试中出现卡死时保留日志、进程及窗口状态；只有已确认属于测试实例的进程可以用于清理，不批量结束同名程序。
