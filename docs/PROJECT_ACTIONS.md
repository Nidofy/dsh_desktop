# Project Actions（0.2.0 开发中）

入口：Help → 会话诊断 → 项目操作。输入工作区绝对路径，读取工程 `.dsh/project-actions.json`；也可以直接在页面编辑并保存到本机 DSH 用户数据目录。保存本机配置后，它优先于工程内配置。

```json
{
  "schemaVersion": 1,
  "actions": [
    {
      "id": "unit-tests",
      "label": "单元测试",
      "command": "python -m unittest discover -s tests -v",
      "cwd": ".",
      "timeoutMs": 600000,
      "env": {}
    }
  ]
}
```

命令由 DSH 原生 PowerShell 执行。项目仍需安装自己的编译器、Python 等工具链。构建环境初始化可以显式写入命令；失败应检查完整命令返回码，不要在末尾用无关成功命令掩盖构建失败。`cwd` 为工作区内相对目录，不接受 `..` 或指向工作区外的目录链接。环境变量明文保存，不应填写密钥；运行时管理的 DSH/Node 环境变量禁止覆盖。

保存不等于信任。检查完整配置、勾选确认框，然后点击信任；信任绑定完整配置及 canonical 工作区。工程内配置变化会失去匹配的信任。本机保存同样内容可继续匹配已批准的内容；没有新增命令授权。脚本文件与源代码仍会正常变化，信任并不验证被命令调用的所有脚本依赖。

UI 运行使用 workspace-write 权限。Agent 的 `run_project_action(id)` 使用当前会话权限；配置可信并不意味着可以绕过 sandbox。失败不会自动以完全权限重试。Agent 的 `list_project_actions()` 只返回操作摘要与信任状态。

同一工作区只执行一个操作，其他操作排队。取消等待中的操作不会结束前一个操作。正在执行的取消通过 DSH 原生命令服务终止进程。配置或信任在排队时改变，则排队操作拒绝执行。

日志与结果保存在 `DSH_HOME/desktop-actions/<workspace hash>/runs`；每工作区最多保留 100 份完成记录，日志每份最多 1 MiB，截断会标记。日志可以含工程内容，和默认不含正文的会话诊断分开，不自动上传。

`UNKNOWN` 表示执行/记录失败，无法确认副作用；`INTERRUPTED` 表示上次引擎退出时没有最终结果。两者都需要先检查工作区，不自动重跑。这里的恢复记录只覆盖 Project Actions，完整 Agent 任务恢复仍在 0.2.0 后续实施清单内。

该页与连接设置、诊断和 A/B 页共用 DSH 主题，跟随 DSH 设置中的外观与字号；无需在桌面另设主题。
