# 下一阶段：源码引擎接入，继续使用 Tauri

建议将下一轮定义为 0.2.5 的引擎适配迭代，具体候选编号按发布流程决定。先让现有桌面能力运行在可维护的源码引擎上，再吸收官方桌面的功能。无需重写 Electron 外壳，也不应立即让新引擎读写正式用户数据。

依据为本地 Harness `00102833dfaee1da9f48a3a8eae9d34005a75218`，而非对所有上游版本的承诺。源码构建和独立 Web Host 已验证，原生桌面新引擎组合尚未验证。

## 第一批：把现有能力接到新引擎

### 1. 启动、配置和数据迁移（最高优先级）

上游已采用 profile/bundle 配置组合，旧 `settings.yaml` 会一次性导入活动 profile 的 `cordis.patch.yml`。当前桌面的设置事务、连接应用和外观同步仍基于旧接口，不能让双方分别写同一项设置。

具体工作：

- 为 Tauri 创建自有 profile（例如 `dsh-desktop`，不能用上游 CLI 保留给 Electron 的 `desktop` 名称），从 Web 模板启动；保持现有本地鉴权、端口监督、进程退出和单实例语义。
- 提取版本化的 Harness 适配入口，替换旧深层导入与初始化假设；先在 0.2.4 的候选环境中运行。
- 将提供方/模型配置映射到新 profile 与 credentials seam；Windows 凭据管理器继续持有密钥，普通 YAML/诊断中只放引用。明确桌面连接与原生模型设置的唯一写入责任。
- 使用复制的合成旧 home 验证迁移：工作区、多个连接、主题、skills、AGENTS/CLAUDE 规则、附件、归档以及重复工作区恢复。
- 新源码 session writer 的格式常量为 4，旧引擎为 3。验证旧会话读取与续写、失败重试和恢复，不让旧 EXE 回写新格式；回退恢复迁移前的数据副本，不能假定只替换 EXE 就能降级。

交付：独立可运行的 Tauri 候选目录；迁移前后样例与恢复证据；默认正式数据保持原状。启动失败须给出具体可操作错误，保留原始资料。

### 2. 原生提供方管理与下一请求生效（直接改善体验）

上游 `packages/llm/llm-pi-ai` 已在每次请求解析 profile 与凭据，配置修改可以在下一请求生效。优先利用这个能力解决现有“切换提供方需要重载后端”的体验，而不是继续扩大桌面私有设置逻辑。

- 多个提供方的模型同时出现在选择器，标明来源，避免同名模型混淆。
- API Key、Base URL、模型参数等在下一请求使用新值；进行中的请求保持创建时配置，旧回调不能写入新连接状态。
- 代理、企业 CA、进程级网络参数单独判定是否仍需重载，不笼统承诺所有设置热更新。
- 借鉴上游 catalog / 模型发现，但让用户确认采纳模型；自定义内网仍可完全手工配置、离线使用。

验收：两提供方相同模型名、双协议、任务中修改、空凭据/撤销、下一轮生效、网络配置重载提示及失败恢复。

### 3. 任务、恢复、通知、桌宠和缓存契约

这些是本项目积累最多的适配点，应在同一批完成，避免产生“能打开页面但原有能力退化”的候选版。

- 将 task-recovery、diagnostics、notifications、pet 连接到新结构化事件与最小状态视图；核对完成/失败/取消/等待、冷恢复、多会话、乱序去重、连接代际。
- 保留锁屏期间后台运行和解锁重连检查；复测服务端断流、长时间无输出、任务已结束但 UI 卡在思考中的恢复。
- 旧缓存扩展绑定旧 adapter 的 hash 与 `onPayload` 接口，不能直接把新文件 hash 填进去跳过审查。核对新请求管线；优先用公开扩展点，必要时在 fork 增加小范围、可测试的请求 hook。
- 使用同一组本地 OpenAI/Anthropic mock 对比升级前后最终 HTTP 请求：tools、history、系统前缀、重试、压缩、cache key/标记和 usage 字段；允许的上游语义变化必须逐项记录。缓存收益另由真实网关观察，不能从构建通过推出命中率提升。
- 迁移环境浮窗、项目操作、Git/Hg、文件产物与主题入口到新版客户端 API，保持用户既定交互，不重新做一套导航。

交付：现有桌面能力的对照清单、协议回归与新 Tauri 原生检查；完成后才开放正式源产物接入。可以每日产出候选供体验，不必等所有后续功能做好才试用。

## 第二批：吸收官方 Electron 的高价值功能

Tauri 决定窗口与原生宿主；功能可通过 Rust/Tauri bridge 实现，不依赖更换桌面框架。官方参考见 [固定提交的 Desktop README](https://github.com/deepseek-ai/deepseek-harness/blob/00102833dfaee1da9f48a3a8eae9d34005a75218/apps/desktop/README.md)。

| 功能 | 借鉴方式 | 优先级 |
|---|---|---|
| 后端/渲染器故障恢复 | 在现有运行状态上补充有界错误报告、重启、备份后禁用第三方插件、安全启动；保留会话与连接 | 高，第一批期间即可做 |
| 共用 Web 插件管理 | 复用官方安装/启停/配置能力，Tauri 只提供必要宿主桥接；内网支持本地离线插件来源 | 高，新 profile 适配后 |
| 本地首屏与明确启动状态 | 参考先加载本地页面再注入 Host 连接的流程；减少后端启动失败时空白页和状态误判 | 高，结合启动适配 |
| 原生目录选择器 | 父窗口恢复/聚焦、并发请求共享一次对话框、取消可重试 | 中，可独立小步完成 |
| 可选离线工作依赖包 | 借鉴 `load_workspace_dependencies`，提供固定 Python/Office 库和工具路径；作为额外模块，核对大小与许可 | 中，有明确文档/表格任务后接入 |
| 统一版本、签名与整包升级 | 沿用现有整包绑定/校验，再增加版本展示、离线包升级与回退；签名需证书和发布基础设施 | 中 |
| 嵌入浏览器、账号/平台视图、语音 | 涉及额外权限、令牌边界和 UI 生命周期；有实际使用需求再做 | 后续 |

不为了对齐官方而引入联网强制更新、账号前置流程或未经选择的遥测。内外网都能使用、稳定恢复和缓存效率仍是主目标。

## 维护边界与完成标准

引擎 fork 仅保存上游无法提供的少量接口/修复；Tauri、环境浮窗、桌宠、凭据、内网策略和离线交付仍在桌面仓库。同步通过固定提交和完整产物进行，避免再次演变成直接修改已安装 node_modules。

本轮基础设施完成后，最值得立刻开的下一项是 **“新引擎的独立 Tauri 候选 + profile/会话迁移”**。提供方热应用及恢复/缓存检查随后接上；Office 工具包与嵌入浏览器不会成为引擎适配的前置依赖。

发布条件：完整源码来源可追溯、旧数据迁移可恢复、双协议与前缀检查、现有功能回归、原生 Windows 启停/锁屏/宠物检查、离线目录完整性均有实际结果。CLI 或 Web HTTP smoke 只能证明对应层面，不代替 Tauri 窗口和目标内网验收。
