# 任务状态与恢复（0.2.0 开发基线）

入口：Help → 会话诊断 → 任务状态与恢复。

页面按当前连接读取 DSH 原生会话，展示最新一轮的状态、最后确认记录时间、最后模型输出状态、最后工具结果和待确认的调用。点击「打开原会话」通过 DSH 的 `uiWorkspace.openSession` 定位原会话，桌面宿主随后恢复主窗口；不会自动提交 prompt 或重放工具。「查看项目操作」带入原工作区，可检查构建记录和日志。

## 状态含义

- **运行中断**：DSH 原生日志中有未正常结束的轮次，原生冷读或恢复逻辑将其判为 interrupted。时间是最后确认记录时间，不是猜测的崩溃时刻。
- **未知**：没有足够记录确认结果。特别是工具调用有记录但缺少对应结果时，实际副作用未知，不能直接重试。
- **已结束**：原生 turn/end 的 completed 状态，不代表编译、测试或用户验收通过。
- **失败 / 已取消 / 等待处理 / 达到输出限制**：保留原生 turn/end 原因。
- **等待权限确认 / 等待用户输入**：当前活跃任务有未结束的原生批准请求或用户提问工具调用。中断后不会继续显示为仍在等待。
- **无记录**不证明没有执行或没有副作用；诊断和恢复读取都无法补回进程退出前未持久化的数据。继续前应检查工程当前状态。

## 实现边界

`desktopTaskRecovery` 是 DSH `sessionProjections` 中的纯事件投影，由原生投影缓存持久化。读取通过 `sessionQuery.observeSession` 的准确观察点；冷读可重建，缓存不是事实源。不维护第二份 Agent 会话日志，也不修改模型请求、工具 schema 或原有消息。

投影只保存轮次/步骤、状态、时间、序号、工具名和有限的待确认调用。工具/权限关联 ID 用定长摘要关联，不保存命令、参数、模型文本、工具结果正文或批准原因。并行待确认调用最多 64 个，超过后明确标为 PARTIAL。

页面还读取原生日志中的会话标题及工作区供本地识别，因此页面/API 不是去标识导出。恢复 API 使用现有 DSH 身份验证；只读列表每页 20 个，单批冷读并发 4。没有定时扫描全部历史；用户主动刷新。桌面窗口定位接口限制为同源 JSON，宿主轮询的只是不含内容的递增通知号。

客户端扩展通过 DSH 官方客户端模块声明加载，没有改原生主界面布局。跨窗口仅发送会话 ID 和导航请求号；主界面先向已认证服务确认会话存在，再调用原生导航服务。退出或连接切换后不同服务端口隔离频道。

## 已验证与后续

- 两协议实际 DSH：采集关闭时也能读取恢复状态；正常结束、原生工具结果、取消、失败；强制终止模型请求后冷读为 INTERRUPTED / UNKNOWN；读取不产生新请求。
- 浏览器使用实际 DSH：恢复按钮定位 `SYNTHETIC_CRASH_FIXTURE` 中断会话，输入框为空、原有 1 轮 1 步保持不变。恢复页使用共享 DSH 主题。
- 原生 Tauri 主窗口恢复分支已接入；完整桌面窗口操作、等待输入/权限的现场体验、重型会话读取性能仍需后续验收。
- 本功能不恢复工作区文件。文件快照、冲突检测、Git/Hg 变更关联、通知和恢复提醒仍按 0.2.0 计划继续。
