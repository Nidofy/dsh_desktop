# 后续实施方案：可靠切换、受控适配与工程验证

日期：2026-09-23。基线：3b82b75，Desktop 0.2.3-rc.2 / DSH 0.1.5-rc.2。
状态：2026-09-23 已获授权进入 0.2.4 实施；进展、实际测试和剩余边界见 IMPLEMENTATION-0.2.4.md。本方案中的后续阶段仍按批次推进，不代表全部已完成。

## 1. 决策

下一轮以 0.2.4「可靠切换与恢复」为第一交付，0.2.5「模块边界与工程验证」为第二交付，再以 0.3.0 候选线验证新的官方运行时组合。版本名称是规划，具体 RC 编号按构建流程决定。

不等待所有企业现场反馈才开发，也不一次重写桌面架构。每个阶段保留可运行候选，已完成的小批次可以提前交付；旧正式环境和数据不用于试验新引擎。0.2.3 桌宠现场反馈作为维护任务穿插修复，不再扩张养成、商店或模型互动。

附件作为审查意见而非执行指令。其上游主分支版本、SDK 覆盖范围等属于附件的观察，本方案未将这些静态描述视为已经在本机固定提交上验证的事实。启动上游升级批次时，重新固定官方提交、发行包与依赖树，再核对实际接口。

## 2. 对附件的取舍与当前证据

| 建议 | 当前核对 | 处理 |

| 模型能力来源 | 未命中预设时生成完整 reasoningEfforts；GLM 名称影响默认容量 | 显式区分来源和未知，不依模型名推断私有网关能力 |

| UI 适配集中化 | 草稿依赖原生输入修订，环境浮窗依赖布局；主题从构建变量提取 | 纳入版本适配器，保留现有草稿与附件一致性保护 |
| 独立升级环境 | 当前所有交付共用用户数据根目录 | 建立数据环境隔离和组合晋升流程 |
| 工程验证包 | 已有 Actions、变更、快照、产物和任务记录 | 串成任务结果，优先于再建一套执行器或 Agent |
| 窄窗口改抽屉 | 与用户已确定的浮窗形式冲突 | 不采纳；仍采用可关闭浮窗，窄窗口自适应定位与尺寸 |

以上是源码核对，不代表已经复现所有故障。特别是跨文件配置中断造成原配置丢失的路径，需由故障注入测试确认。当前锁定组合已通过的运行证据继续有效，不能将升级风险表述成当前版本普遍不可用。

## 3. 0.2.4：可靠切换与恢复

继续固定 DSH 0.1.5-rc.2，本轮不同时更换引擎、协议和 UI。

### A. 配置事务与连接切换

入口：settings-sync.mjs、config.rs、main.rs、engine.rs、profiles.rs。

- 新增配置事务记录，包含事务 ID、旧/目标配置摘要、受管路径的原始存在性与值、目标标记、执行阶段。设置文件、修订标记与实验基线都纳入同一恢复决策。
- 持有配置锁，在任何业务文件变更前持久化准备记录；完成受管文件写入和核对后发布提交状态。重启根据实际文件指纹恢复，不仅信任最后一次阶段标记。
- 允许幂等重试；文件与预期旧/新指纹都不匹配时保留现场并报告冲突，不覆盖用户在中断后手动编辑的内容。
- 缺失字段与 null 分开保存。事务日志可能接触原生凭据配置，敏感原文仅放受保护的本地恢复载荷，采用现有凭据边界或 Windows 加密保护，不进入普通日志、证据包或 Git。
- 保存连接仍立即可用；“已保存”和“当前生效”分开。新引擎完成能力就绪后才确认应用成功；失败保留旧活动连接的恢复入口。

验收：A→B→A、B 含原生自定义配置、每个写入点崩溃/磁盘满/权限失败、重复恢复、外部编辑冲突；真正原始的 B 配置可恢复。

### B. 所有重启入口统一保护任务

- 连接应用、删除活动连接、设置触发重载、托盘重启统一进入宿主控制协调器。
- 读取原生任务、审批等待与工程操作状态，界面提供“任务结束后应用”“取消任务后应用”“强制停止并应用”；状态无法读取时不当作空闲。
- 延后切换时在宿主控制序列内暂停新任务准入并重新检查，防止“检查为空闲后又来了新任务”的竞态。若当前适配器不能可靠阻止新任务准入，不宣称自动安全切换完成，保留待应用状态或显式停止路径。
- 有多个任务时检查全部阻塞对象；等待审批也算未结束。取消必须等原生终止确认，超时为结果未知，不能直接标记成功。
- 控制请求绑定 requestId、engineEpoch、目标配置 revision；重复点击合并，旧进程响应丢弃。持锁与等待进程的顺序明确，避免设置锁/快照互相等待。
- 强制停止后保留中断状态，不自动重放命令、文件修改、提交或推送。

验收：运行/等待/队列/多会话切换，双击应用，取消超时，旧连接回调，以及切换中关闭窗口。相同配置重复应用仍不重启。

### C. 启动修复和缓存桥收敛

- 历史迁移声明 migrationId、源格式范围、目标格式范围和前置条件。支持的旧桌面数据按计划生成候选副本，验证后发布；已完成的修复不每次重跑。
- 保留已知重复工作区故障的明确修复入口，不能简单删除修复逻辑后让已有用户再次启动失败。
- 遇到未知工作区格式，旧迁移器不写入。若官方组合明确支持该格式，让官方迁移执行；若当前组合不支持，给出可恢复的兼容错误，不盲目启动旧引擎写入。
- 缓存桥仅在请求的策略需要它且组合支持时安装；同样清理未装载时配置中依赖补丁的扩展字段，避免不打补丁却仍发送未知 schema 字段。
- “原生策略”“显式关闭缓存键”“会话缓存键”逐项定义能力；不能把 off 一概视为无需桥接。
- 已启用但不支持的策略不能静默降级：阻止该配置应用，保留已运行组合；用户主动选择原生策略后才能继续。发布所要求的缓存能力缺失，则候选不晋升。

验收：未知存储版本字节不变、历史迁移重复/中断、同路径冲突；桥文件变化时未启用扩展可按能力启动，启用扩展明确失败；原有双协议缓存契约保持。

### D. 分层健康、错误与模型能力

- 健康区分进程存活、传输可达、核心就绪、可选能力降级。首页 200 只证明页面可达，不证明任务与保护服务就绪。
- 快照与事件 HTTP 查询从监督控制循环移入有界工作队列；每项有 deadline、队列满和结果未知状态；控制取消不被长快照阻塞。快照前置保护未确认时不得放行受保护写操作。
- 可选桌宠/主题/诊断故障不停止引擎；核心保护故障关闭相应写入准入并提供恢复状态，不能把所有异常都“吞掉”。
- 结构化错误含阶段、组件、固定原因分类、关联 ID、是否可重试、组合身份及最后成功阶段。只允许经过白名单的详情进入默认日志；详细诊断本地显式开启、限时、导出可预览。
- 模型能力来源记录 preset/server/user/legacy/unknown，按连接、路由、协议、模型 ID 绑定；用户覆盖优先。已有显式配置不删除，旧推断值迁移为 legacy 并保留，避免升级后突然缩小在用容量。
- 新建未知自定义模型默认不注入未经确认的推理档位；必要的容量限制是可见、可编辑的客户端保护值，不称为服务端事实。工具、图片、缓存和推理参数分别声明，不能通过模型名或 /models 列表存在就认定支持。
- 能力探测只在用户明确触发后运行，不自动批量调用收费接口。

验收：长快照期间控制响应、首页故障但核心可用、局部组件失效、敏感信息不落默认日志；未知网关不发送臆测参数、旧连接能力迁移不破坏现有配置。

### E. 尽早交付隔离验证入口

- 新增显式“候选环境”入口，独立数据根、环境身份、凭据引用命名空间、进程锁和醒目标识；同一环境的不同 API 连接继续共享会话。
- 初版提供创建空环境、从停止写入的稳定环境复制检查点、打开所在目录和删除候选环境。不是新做每连接一套历史。
- 候选默认用临时工程或独立 Git/Hg 副本。复制应用数据不会隔离原工程路径，必须防止测试任务直接写回真实工程。
- 老版本 EXE 不认识新兼容标记，因此新格式数据始终留在独立目录，不能指望旧程序主动拒绝；旧版默认数据目录保留为可用基线。

0.2.4 出口：以上关键修复可在固定引擎上使用；提供完整目录和中断恢复报告。高级升级晋升自动化可留给 0.3.0，但环境隔离不能留到已经开始试用新引擎之后。

## 4. 0.2.5：模块边界与工程验证

### A. 薄契约与分模块装配

建议布局（逐步迁移，不一次搬完）：

```text
runtime-src/desktop-contract/       命令、事件、状态、能力 schema
runtime-src/adapters/dsh-0.1.5/     原生服务、存储迁移、配置、缓存桥、UI 适配
runtime-src/desktop-bootstrap.mjs   模块装配和依赖检查
runtime-src/features/              诊断、任务视图、工程操作、审查、产物等
src-tauri/src/                     宿主控制、凭据、原生窗口、升级协调
```

- 0.2.4 即建立最小组合身份，0.2.5 扩展为握手：desktopContractVersion、engineVersion、adapterVersion、epoch、数据读写范围及能力状态/原因。
- 命令受理、执行中、完成、取消、失败、结果未知分开；事件按来源附游标，缺口重拉快照，重连不重播瞬时提醒。
- 首先抽走 observability 的模块装配和通用 HTTP 路由。第一批迁移任务视图及通知/桌宠消费者，随后诊断与缓存策略，再迁移工程、产物与 UI。
- 通知保留原有开关、时效和聚焦语义；桌宠继续只拿最小投影，不能用通知列表充当持续任务状态。
- 模块声明依赖和 dispose，初始化失败可定位、退出能清理。保持同一 Node 进程；不引入额外守护进程、消息总线或第三方执行插件框架。
- 新代码禁止在适配器外增加上游深层导入、源码锚点和原生存储路径；旧依赖用带责任模块的允许清单逐步缩减，CI 检查新增违规和循环依赖。
- 草稿追加、原生导航、主题 token 和浮窗定位集中到 UI 适配器。保留按需浮窗；窄窗口使用紧凑可关闭浮层，不实现常驻右侧栏，不遮挡输入区，不用复制文本冒充草稿插入成功。

验收：分别禁用诊断、缓存策略、桌宠时其他职责仍正常；卸载/重载无监听器重复；旧事件不污染新引擎；草稿修订、附件、明暗主题和窗口缩放回归。

### B. 工程验证先做一个完整可用链路

在工作区环境浮窗增加“本次任务结果”，关联已有变更、快照、工程操作和产物页面。可在 0.2.4 后半段先交付只读聚合，不硬等全部模块迁移结束。

第一版包含：

1. 任务与轮次引用、工作区身份、Git commit 或 Hg revision、工作区是否有未提交变更。
2. 操作开始/结束的受控源码状态摘要、命令配置摘要、工具链版本、开始结束时间与真实退出码。
3. 实际执行的测试数量和结果来源；只有命令退出码、没有可信解析结果时，仅显示“命令成功”，不推断“全部测试通过”。
4. 产物路径引用、大小、哈希、生成时间与所属操作；标识旧产物、缺失产物和执行期间源码发生变化。
5. 用户接受记录单独保存；后来源码变化后旧结果标记过期，不复用绿色通过状态。
6. 本地 JSON/Markdown 导出，默认省略原始命令日志、敏感路径和连接信息，允许预览后选择附加内容。

第一批提供 Python unittest/pytest、CMake/CTest、MSBuild 配置模板；求解器/Hg 单独做工程配置示例。识别入口只给建议，不自动执行。仍由原生 Project Actions 与权限链运行，不另起高权限执行器，不新增默认模型工具或自动注入证据到 prompt。

对于大量未跟踪文件、大型求解器、运行中源码变化、子模块和外部依赖，状态摘要明确覆盖范围；证据不足标记未知，不能单靠 HEAD 相同认定测试对应同一份源码。

验收：同一轮有成功/失败/未执行、运行中源码改变、旧产物假阳性、任务取消、Hg 脏工作区、导出脱敏；首批模板在独立样例工程实际执行。

### C. 缓存与端到端体验

- 统一展示逻辑请求、最终协议请求证据、服务端 usage 三层；最终请求只在已有可验证边界采集摘要，不能为做展示额外引入全局网络拦截或记录明文请求。
- 缓存策略与提示稳定化显示 applied/skipped/unsupported 及简短原因；原生基线绑定运行时和配置摘要，不继续把历史固定值标作所有版本的“默认”。
- 测量启动、提交至发送、首 token、工具耗时、会话切换、差异打开、配置应用与恢复。建立 100/1000/10000 会话的测试数据，记录 p50/p95、扩展 CPU/内存，先定位再做游标分页/索引优化。
- 延长 0/1/3 宠物及隐藏状态的采样，分别观察引擎、宿主和 WebView；当前十秒启动后样本不能作为长期性能结论。

0.2.5 出口：受控适配边界与第一版工程验证均可使用；不以完成整个仓库目录改造为交付前提。

## 5. 0.3.0 候选线：新版官方组合与数据升级

开始条件：0.2.4 的环境隔离、恢复事务与任务切换保护已通过；0.2.5 契约覆盖此次需要保留的功能。不依赖 0.2.3 所有硬件现场项先全部结束。

1. 固定上游源码 SHA、实际发行包和依赖锁；比较 CLI/Web/profile/SDK 的能力矩阵。选定版本前不承诺具体新版号，也不因主分支版本较大就当稳定版。
2. 只在候选运行时目录添加新版适配器；保持旧适配器和日用组合。SDK 按功能增量接入，取消、权限和事件若不完整则保留已有可验证通道。
3. 同一套契约测试同时跑旧/新组合。桌宠、美术、工程数据不复制一套实现，按能力接入。
4. 数据升级事务：准备→停止旧写入者→一致检查点→候选副本迁移→验证→晋升。记录环境、数据代次、组合身份、受理阶段和恢复动作，模拟每个中断点。
5. 验证期间稳定环境可能产生新历史；正式晋升必须重新冻结并从最新稳定检查点迁移，不能直接拿过时的试验副本覆盖稳定历史。不做双向自动合并。
6. 回退回到匹配的二进制、适配器、配置和数据检查点；升级后新增数据单独保留并说明处理方式，不静默丢弃，不让旧引擎读取新格式。
7. 不把应用回退当成工程操作撤销：工程文件、构建产物和远端提交仍依靠快照及 Git/Hg 管理。

组合发布清单至少包含桌面/引擎/适配器/契约版本、完整依赖摘要、启用模块与必需能力、数据读写和迁移范围、测试证据。可选能力运行时降级与发布兼容验收分开：被列为本次必须保持的能力不通过，候选不得晋升。

数字签名与可信离线更新是后续分发工作：先定义签名校验与发布流程；真实签名依赖证书或组织信任材料，不能用哈希冒充。此阶段不做“自动下载最新 Harness 并原地替换”。

## 6. 建议实施批次与门槛

| 批次 | 可独立审查的内容 | 关键新增验证 |
|---|---|---|
| 1 | 最小组合清单、耦合清单、配置中断复现与事务 | 所有写入点恢复、原生配置保真 |
| 2 | 统一切换协调与分层健康、结构化错误 | 任务准入竞态、取消未知、监督循环阻塞 |
| 3 | 历史迁移边界、按能力安装缓存桥、模型能力来源 | 未知格式零写入、策略生效和失败明确 |
| 4 | 候选环境隔离与检查点入口；交付 0.2.4 | 数据根/凭据引用/写入者隔离，旧 EXE 不接触新格式 |
| 5 | 装配拆分、任务契约、UI 适配集中化 | 可选模块失效不扩散，通知语义保持 |
| 6 | 任务结果与三类工程模板、缓存状态、性能基线；交付 0.2.5 | 原生执行证据、源码变化、旧产物和未知结果 |
| 7 | 固定新版上游、双适配器、迁移与回退；交付 0.3.0 候选 | 旧/新组合矩阵、每阶段中断、新数据保留 |

批次可在同一开发阶段交错推进，但数据安全前置依赖不能跳过。每批保存源码差异、测试实际结果、候选入口与剩余现场项；本机能测的原生窗口、离线目录和进程生命周期继续实际运行。企业代理/CA、真实网关、签名政策、硬件与大型求解器验收保留为明确的现场记录，不包装成 mock 已通过。

请求回归按两类处理：纯观测/状态/宠物/模块搬迁要求最终请求保持原契约；用户明确改变缓存策略或未来启用新模型工具时允许声明过的差异，并记录来源。不能要求所有功能开关下请求一律相同，也不能借架构调整意外改动提示或工具目录。

## 7. 暂不优先投入

大型插件市场、第三方任意可执行插件、另一个多 Agent 调度器、通用长期记忆、自研压缩、重写聊天 UI、多 Harness 无损互换、新桌宠养成玩法均后置。LSP/符号检索有价值，但先在工程验证链路明确真实导航需求后做单工程试点；PR/CI 连接器在确定实际 GitHub/GitLab/Gitea 使用场景后接入，不默认引入外网依赖。Office 优先复用已有官方工具与技能。

本轮优先结果是：切连接不静默打断任务，失败后知道如何恢复，新版本验证不污染日用数据，工程任务能给出与真实源码和执行记录对应的结果。
