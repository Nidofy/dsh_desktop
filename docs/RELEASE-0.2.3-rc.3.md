# 0.2.3-rc.3 桌宠修复

用户在 RC2 设置页启用桌宠后遇到透明空窗和应用无法退出。同步 Tauri IPC 命令直接创建 WebView2，阻塞 Windows 事件循环；依赖源码 tauri 2.11.5 的 `WebviewWindowBuilder` 文档明确列出此限制。之前预设 enabled=true 的冷启动验收不覆盖运行中启用路径。

修复：

- `pet_settings` 使用异步命令和 `spawn_blocking`，原生窗口创建不再阻塞 IPC/退出所在的事件循环。
- 新窗口先保持隐藏，移除继承菜单并恢复位置后再显示，避免创建时出现白色菜单条。
- 宠物设置采用同排开关、角色/缩放网格和分组折叠；心情、气泡与资源管理按需展开。
- 保存中显示应用状态，失败后刷新已保存配置并保留错误；恢复警告不再被“已保存”覆盖。
- 保存期间的连续修改和已确认基线有单独回归测试。
- 构建同步自动移除 runtime 根目录中已不属于本版源码的 `.mjs` 模块，保留 Node 与上游目录；复用构建环境时不夹带其他版本的桌面模块。

本修复包从完整已提交的 0.2.3 基线 `3b82b754d568a8a87523e7f729e9a91bc4ecf07b` 建立独立工作树，不含开发中的 0.2.4 配置事务与缓存桥改动。既有 0.2.0/RC2 发布目录保留。相同功能修复已带回 0.2.4 工作树，未自动提交或推送。
