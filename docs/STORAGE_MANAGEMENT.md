# 本机存储管理（0.2.0 开发基线）

入口：Settings / Diagnostics → 本机存储管理。按连接列出桌面扩展的记录，选择时间范围、类别及具体记录后手动清理。不会定期执行，也不上传记录或发送模型请求。

## 使用

1. 载入连接列表，选择需要管理的连接，默认列出 30 天以前的记录。可选 1 / 7 / 30 / 90 天或全部，按一份记录中最新修改时间判断。
2. 扫描后按类别查看，显示编号、时间、文件数和大小。默认没有选择；批量选择最多 200 份，并始终排除文件恢复备份。清理备份须单独启用并逐份选择。
3. 结束正在运行的任务，确认永久删除及重启引擎。清理完成会尝试启动当前已配置连接，不自动重发任务。实际启动结果看顶部引擎状态。
4. 检查逐项回执。结果为已清理、未清理或部分完成；部分完成无法撤销，没有自动重试。重新扫描会清空旧选择，保留本次回执。

原生会话、工作区、连接配置与凭据、操作配置和信任、缓存能力声明均不在此入口的清理范围。文件恢复快照会包含源码和恢复前内容，清理后会失去这份恢复能力。需要长期保存时先自行完整备份。

## 管理范围

| 类别 | 当前连接 DSH_HOME 内的位置 | 清理单位 |
|---|---|---|
| 诊断采集 | desktop-measurements | 一份 UUID JSON |
| 缓存探针 | desktop-cache-probes | 一份 UUID JSON |
| 自检报告 | desktop-self-tests/reports | 一份 UUID JSON |
| 比较基线 | desktop-changes | 一份 UUID JSON |
| Project Actions | desktop-actions/工作区指纹/runs | 同一 UUID 的 JSON 与日志 |
| 导出临时副本 | desktop-artifact-exports | 一份 UUID tmp |
| 自检遗留目录 | desktop-self-tests/fixtures | 一份 UUID 目录，必须含匹配的 .owned 标记 |
| 文件恢复备份 | desktop-task-snapshots | 一份 32 位十六进制编号目录，含开始/结束/恢复记录与内容 |

统计是已识别且可检查的受管记录总量，不是整台电脑、整个连接或所有原生会话的磁盘总量。超限、链接、不可读项目显示警告且不计入可清理清单；有警告时统计不完整。未知名称保留原样。只列出当前连接目录表中的连接，被配置回退隐藏的旧连接可先恢复配置再管理。

清理扫描每次最多 10000 项，单份目录最多 4096 项、16 层；界面一次展示最早 200 份，可筛选类别。超过这些限额不会猜测删除，需人工归档。凭据引用清理和快照归档现已提供独立入口；跨连接写入配额与额度设置已接入。

## 所有连接的总览与写入配额

设置页「所有连接的存储总览」独立扫描固定用户数据目录下的旧版 `dsh` 和 `profiles/p-<32 hex>/dsh`，因此也包含配置回退后隐藏的旧连接。统计七个桌面受管目录内的全部普通文件，包括 `.new`、未知名称、恢复记录和 Project Actions 配置；这是容量统计，不代表未知文件可以安全删除。它不包括原生会话、工程、运行时、WebView 缓存及系统日志。

全局扫描最多 1024 个连接目录、200000 项、32 层。只读取文件元数据，不读取源码内容；链接、硬链接、附加数据流、不可读/特殊项目或扫描超限使统计标记为不完整，此时剩余额度为未知且拒绝新的受管写入预留。页面不把未知显示为零。

共享额度层默认为 2 GiB，按「已计量文件 + 正在预留的最大增量」执行桌面受管写入准入。额度预留串行，同一份空闲容量不会同时授予多个操作；操作结束或失败释放预留，下次按实际落盘文件重新统计。正在写入的文件可能同时计入现有占用与预留，因此这一阶段采取保守估计。已有记录不会因为总量超限自动删除。

原生手动/自动快照采集、确认/封存、恢复前备份和归档导入，以及 Node 侧诊断、缓存探针、自检、比较基线、项目操作与导出暂存，均接入同一额度层。固定受管目录外的原生历史、投影和少量有独立大小上限的设置文件仍不属于此额度范围。

- 一般 JSON/日志原子写入按编码后字节数的两倍预留；任务内累计写入也计入上限，涵盖临时文件及多次检查点。
- 项目操作在排队前预留 3 MiB，包含状态和最大 1 MiB 日志；自检启动前预留 64 MiB，包含固定合成工作区与检查点；缓存探针启动前预留 2 MiB。未获额度时不执行对应命令或探针请求。
- 导出暂存按源文件大小预留。原生采集/恢复按 32 MiB 加元数据，导入按 256 MiB 上界预留。各模块原有较小限额继续生效。
- 任务获准后即使其他写入耗尽余额或用户降低配额，仍可在已有预留内保存完成/取消记录。撤销项目操作信任删除本机授权文件，不因额度不足而被阻止。
- 私有引擎管道传递额度申请和释放，不进入模型上下文。申请超时不重试文件写入或模型请求；不确定申请会清理对应预留。幂等释放最多尝试两次，若回执仍未知，原生端保留额度直到引擎退出，避免提前重复授予。正常结束显式释放，进程退出后由原生管理器释放该引擎剩余预留。

总览扫描后可设置 256–65536 MiB 的整数上限，默认 2048 MiB。设置立即生效且不重启引擎；降低至已有占用/预留以下允许保存，但新写入会被拒绝，不自动删除记录或取消任务。配置保存在用户数据根目录的 `desktop-storage-quota.json`，独立于连接回退；原子保存并核对修订号，旧页面不能覆盖新设置。文件损坏、异常链接或读取失败不会默默使用默认额度，应保留文件并修复；文件占用导致保存失败时原设置保留。

诊断或自动快照无法写入时沿用其原有降级行为，不因此阻断普通模型任务；这类任务可能缺少相应记录或可恢复快照。Project Actions、自检和探针需要先为自己的结果记录获得额度。

外部应用修改本机存储不属于此应用的写入准入范围。扫描不是操作系统磁盘配额，也不保证系统盘可用空间；每个模块原有上限继续生效。

桌面系统日志已有每文件约 2 MB、上一代滚动文件的轮换，当前入口不删除正在使用的系统日志。原生 DSH 会话及日志仍由 DSH 管理。

## 实现约束

- 只有打包的本地 Settings 窗口可以调用 Tauri 存储命令；远程 WebView 和模型工具没有这个权限。
- 预览允许文件原子轮换，不阻断正常引擎写入。预览 token 绑定连接目录、记录编号、父目录身份以及所列文件的身份、长度、创建/修改时间；不是内容 hash 或文件系统原子快照。
- 清理由 supervisor 在旧引擎退出、子进程 Job 释放后执行，然后进入正常启动流程。即使清理未启用连接，也会重启当前引擎。读写连接、恢复、快照和清理使用同一原生锁。
- 实际删除前从磁盘根固定父目录句柄，不经过 canonicalize 跟随链接。文件独占打开并重新检查 token；占用、变化、目录链接、硬链接、附加数据流、加密或离线文件拒绝。
- 删除使用已经检查的 Windows 句柄，先子项后目录，不调用任意递归删除命令。自检目录中的 Git/Hg 元数据只属于身份已核对的合成工作目录；不触及真实工程。
- 多份记录逐份处理，单份目录内也可能部分成功。例如只读项阻止删除时，已有成功项不会回滚；失败/退出没有重放队列。外部新增项不会被此前枚举的句柄集合删除，目录非空会导致清理不完整。
