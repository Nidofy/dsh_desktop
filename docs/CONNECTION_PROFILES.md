# 多连接与内外网边界（0.2.0）

工作区右上角「环境信息」→「本地」→「连接与模型」 中可新建和选择连接。每个连接独立配置模型、凭据、代理、企业 CA、请求超时和流空闲超时。

## 日常操作

1. 顶部选择「DeepSeek 官方连接」「添加提供方」或「添加自定义提供方」。前两项从随包 DSH 目录填入默认配置，只需输入 API Key；自定义提供方填写 Base URL、协议和模型。已知提供方的地址和模型仍可在「自定义设置」中调整。
2. 点击「保存连接」。保存不重启引擎，不中断当前任务。
3. 当前任务结束后点击对应提供方的「应用」。失败时留在诊断页，可选择原连接重新启动；没有自动连接回退。

已保存连接支持修改地址、协议和模型，也可删除。删除当前连接时选择另一个连接；删除最后一个连接后回到未配置状态。删除连接不删除工作区、会话或文件。

## 存储与兼容

所有连接共享 `%LOCALAPPDATA%/DSHDesktop/dsh` 中的工作区、会话、附件和界面设置。旧 `profiles/<id>/dsh` 的会话、附件和工作区列表在启动时合并一次，保留原目录；同路径内容冲突时停止迁移并保留双方数据，不覆盖。迁移标记保证后续启动不会重新导入已处理历史。旧连接的诊断和快照目录继续保留，存储页可查看其占用并选择清理。

## 配置恢复

设置页「连接配置恢复」可预览最近保存前、最近回退前、旧版单连接三种固定来源。显示连接名称、地址、协议、模型数量、下次启动所选连接及本机凭据/网络路径可用性；不会显示 API Key，也不会为预览发送模型请求。网络路径检查通过不代表实际服务连通。

1. 点击「预览配置备份」，选择可用来源，检查将恢复的连接及暂不显示的连接。表单有未保存内容时，先保存或明确重新载入。
2. 勾选确认后恢复。当前 `connections.json` 先原样保留为 `connections.recovery-before.json`，再原子替换；`connections.previous.json` 不会被回退操作覆盖。
3. 当前引擎继续使用原连接。任务结束后，点击「应用」应用。若需撤销回退，预览并恢复「上一次回退前的配置」。这是一个滚动备份位，下一次回退会替换它。

损坏但可读取且不超过 2 MiB 的当前 JSON 也可以恢复；原文件保留供排查，但不会伪装成可用回退来源。当前文件为链接、不可读取、目录或超限时停止恢复，需先人工处理。没有有效备份时不自动创建或切换服务。

预览 token 同时绑定当前文件与备份内容，任一变化会拒绝旧操作。桌面操作共用保存锁，提交前再次核对当前文件；不将此机制宣称为对外部编辑器的操作系统级原子比较交换。恢复后的修订号递增，旧设置页面不能直接覆盖结果；当前有效配置中同一连接 ID 不允许改变地址或协议。恢复只修改配置，不搬动或删除历史目录；不存在的凭据和 CA 需在恢复后修复。旧版恢复将可用旧凭据复制到独立引用，JSON 不含密钥。

仅打包的本地设置窗口有恢复权限。回执丢失或异常时不自动重试，须重新载入并预览确认当前状态。

## 未引用凭据清理

设置页可扫描、逐项选择并确认删除不再使用的连接凭据。仅检查当前 Windows 用户下 `DSHDesktop/InternalLLM/connection-profile-v1/p-<32 hex>` 的通用凭据；旧版 URL 凭据、诊断指纹密钥和其他应用不在范围内。只处理编号和 Windows 写入时间，不读取、记录或返回密钥内容。

- 保留 `connections.json`、`connections.previous.json`、`connections.recovery-before.json`、`connections.new.json` 以及当前运行引擎引用的凭据。任一已有配置不可读取、损坏、超限或为链接时拒绝清理；不会猜测损坏备份的引用。
- 最近 24 小时写入的凭据不进入候选列表。预览绑定配置内容、当前运行引用和全部凭据元数据；删除前重新核对，旧预览拒绝。每批最多 128 项，默认不选择、不自动清理、不自动重试。
- 原生操作与配置保存串行，配置文件在处理期间保持只读锁。引擎启动捕获凭据引用与清理共用状态锁，避免启动与清理交错。无需重启现有引擎。
- 显示逐项删除、已不存在、发生变化或拒绝的回执；中途枚举失败保留此前回执。异常或回执丢失须重新扫描，不能推断整批都未删除。
- 所有便携程序使用同一固定用户数据目录；保留的外部手工配置副本不参与引用检查。应用正常轮换使用不可变的新凭据编号；此机制不承诺对外部凭据管理器或其他进程修改的原子比较删除。

Rust 测试在独立的 `DSHDesktop/IsolatedCredentialTest` 命名空间创建并清理自有随机条目，不删除产品凭据。浏览器 fixture 只操作内存条目；实际 Tauri 设置窗口仍需验收。

## 网络行为

- **继承代理**：沿用 DSH 原生启动环境解析，包括其允许的 home `.env` 设置；默认保留现有行为。
- **直连**：覆盖 HTTP/HTTPS/ALL_PROXY 和 NO_PROXY，避免 home `.env` 重新启用代理。
- **自定义代理**：为 HTTP/HTTPS 设置同一 HTTP(S) 代理；可设置主机/域名后缀绕过列表。暂不支持在代理 URL 中存凭据或配置 SOCKS。DSH 原生策略始终绕过回环地址，绕过列表不支持 CIDR。
- 完整复用捆绑 DSH 的 `dsh-http-proxy`，没有第二套 fetch 代理实现；本机引擎健康检查直接访问回环地址。
- 使用 Node 内置与 Windows 系统 CA。配置的 PEM 文件通过 `NODE_EXTRA_CA_CERTS` 增加信任；不继承外部的 `NODE_EXTRA_CA_CERTS` 或关闭 TLS 校验的环境设置。启动前确认 PEM 中每张证书确实已进入 Node 额外信任库；缺失、损坏或没有成功载入时停止启动。
- CA 文件只接受 PEM 证书块和空白，最多 1 MiB，不接受私钥或其他内容。文件需要在目标机器相同配置路径可读。
- 请求和流空闲超时各为 1 秒至 2 小时，默认 300 秒；直接映射到官方 provider 的 `timeoutMs` 和 `streamIdleTimeoutMs`。没有增加重试次数。
- 代理配置是路由策略，不是系统防火墙或全局无出网证明。真实企业代理认证、企业证书链与内网网关仍需目标机验收。

## 外观

设置窗口读取实际运行连接的 DSH `ui-theme` 镜像。所有连接共享 DSH 外观设置，所有扩展页面仍跟随当前 DSH 的明暗、系统模式与字号，不建立第二份桌面外观设置。

## 验证

- Rust：旧配置迁移、密钥隔离与旋转、地址/协议编辑及连接删除、修订冲突、损坏配置不回退、目录边界、网络启动变量。
- 配置恢复原生测试：损坏当前文件原样备份、过期当前/备份 token、地址改绑拒绝、备份写入失败保持当前、回退/撤销回退、缺失 CA 保留、历史不变、旧 Windows 凭据迁移且 JSON 不含密钥。
- `tests/profile-network.mjs`：本机真实 HTTP 代理请求、直连、继承代理、回环绕过、自签名 TLS 拒绝、企业 CA 接受、无效 CA 阻止启动。开发测试使用 Git for Windows 的 OpenSSL，可用 `DSH_TEST_OPENSSL` 指定路径；产品运行不依赖 OpenSSL。
- `tests/protocol-models.mjs`：通过实际 DSH 引擎分别验证两种协议、模型设置、重启持久化和 真实压缩日志迁移和 A → B → A 历史连续性，切换不发送请求。
- `tests/settings-ui-preview.mjs`：仅供浏览器验证设置页交互和样式。Tauri 桥为内存测试替身，不能作为原生桌面端到端验收证据。
- fixture 可用 `--corrupt` 验证损坏配置启动，`--light` 验证浅色 17px。已验证恢复、未保存保护、双页面过期预览拒绝和撤销回退；不代表实际 Tauri 桥点击已验收。

## 已知提供方目录（2026-09-22）

当前内置 13 个提供方、105 个模型：DeepSeek、智谱 Coding Plan 中国、Z.AI Coding Plan 国际、Anthropic、MiniMax 中国/国际、Kimi For Coding、Moonshot 中国/国际、阿里云 Token Plan 中国/国际、Xiaomi、Cerebras。目录由捆绑 DSH 的 pi-ai 数据在构建时生成，不依赖联网获取；暂未覆盖 DSH 的所有协议与提供方。

已知提供方使用原生提供方路由，继承模型思考档位、输入类型和供应商兼容配置。原生模型设置中已存在的同名提供方在桌面接管前记录原值，切换离开或删除桌面连接时恢复；API Key 仍保存在 Windows 凭据管理器中。自定义提供方继续支持 OpenAI Chat Completions / Anthropic Messages。

启动错误现在输出固定分类码（权限、模块链接、依赖、设置、偏好等），并显示对应中文提示。不会将原始异常、API Key、服务端正文写入日志。
