# 0.1.5 — 配置同步与对话 Thinking effort

0.1.4 只更新启动 overlay；原生 DSH 的 `settings.yaml` 用户配置优先级更高，因此旧 `desktop-internal` 模型及容量仍可能覆盖它。原来的“保存并重启”也仅发出重启信号，没有等待新引擎就绪。这解释了旧模型仍显示以及保存后状态不一致的问题。

0.1.5 在旧引擎退出后、新引擎读取设置前，同步桌面管理的 provider，清除其旧模型和容量。原生文件使用相同文件锁及原子写入机制，修改前备份，保留其他 provider、偏好及 YAML 注释；损坏配置保持原文件并终止启动。连接或容量有变更时应用桌面默认模型；普通重启保留有效的原生模型选择。同一默认模型的原生推理等级在容量修改时保留。

保存按钮等待新引擎真正就绪才返回成功。旧会话若引用已移除的桌面模型，下一轮通过官方选择模型 API 修复为已配置的无 `[1m]` 同名模型或默认模型，保留历史。历史 `request/context` 数字只在下一轮新请求刷新；无需第二次重启。

GLM 5.3 / Flash 未指定容量时，桌面预设为 1,000,000 上下文、128,000 最大输出。显式保存的值保留，设置页提供按钮一次更新。其他模型继续使用 32,768 / 4,096 回退值。这些是客户端预设，不是对实际服务能力的承诺。

Thinking effort 仅使用原生对话模型控件：点击模型，下面选择“推理等级”，结果显示在模型名称后。包含 Default、Off、Minimal、Low、Medium、High、Xhigh、Max；设置/诊断页没有强度选项。OpenAI 使用官方适配器的 reasoning effort 参数，Anthropic 使用官方 thinking 映射，实际可用档位由服务决定。未改动官方 DSH 包源码。

## 验证

- 9 个 Rust 测试通过；设置同步测试覆盖旧配置、其他设置/注释保留、原文备份、幂等性、同模型推理等级保留、损坏输入保护。
- 两种 API 格式均通过真实官方 CLI 回归：先关闭同步重现旧 `[1m]` 覆盖，再在第一次重启修复，继续旧会话并验证 1M 上下文和 128,000 输出参数。随后切换另一模型、重启续聊、修改原生推理等级，验证请求参数、流式输出及 read 工具。见 [协议证据](evidence/settings015-protocols.json)。
- 实际桌面使用隔离 LOCALAPPDATA，点击 GLM 预设、保存后，后端 PID 从 15216 变为 28212，新引擎 4,127 ms 就绪，原生设置成为 1,000,000 / 128,000。原生对话可选择 High，控件和原生默认设置均保存 High。见 [窗口截图](evidence/settings015-thinking.png)。
- 最终构建的 Help 菜单在重启后仍可用，High 选择保留；通过 Help → Quit 正常退出并清理后端。见 [GUI 证据](evidence/settings015-gui.json)。
- 完整离线包运行受限 PATH 和本地 mock 测试，覆盖原生读写文件、PowerShell、重启持久化以及四种 API 错误。最终 ZIP 解压后 257 个 WebView2 文件校验通过，实际桌面 4,992 ms 启动，使用解压目录的内置浏览器；单实例、回环监听、后端崩溃报告和退出清理通过。见 [解压后桌面验证](evidence/settings015-extracted-desktop.json)。

本机为 Windows 11 build 26200 普通用户。没有调用用户 GLM 接口、发送百万 token 请求或在真实 Windows 10 内网机器上验证；完整 MVP 验收仍未完成。
