# RC2 外网反馈修正

本轮依据用户的十二项实际反馈调整产品行为。工作区与会话不再按 API 连接隔离；此前的连接历史隔离方案被本轮要求替代。原始数据保留，迁移完成前不删除旧连接目录。

## 实施范围

- 设置：连接与模型、文件快照、存储、备份凭据、运行状态分组选项卡。
- 诊断：修复顶部链接换行重叠，修复远程 WebView 误用本机 IPC 的主题同步。
- 文案：删除审计结论式说明，保留实际操作提示及删除、覆盖、发送数据的必要说明。
- 菜单：设置窗口去掉再次打开自己的菜单项，统一中文名称。
- 连接：支持地址、协议编辑及删除；共享工作区、会话与界面设置；保留旧数据并提供可验证迁移。
- 工作区：右上角可折叠环境信息与工具入口，包含 Git/Hg 变更、产物、操作、快照、缓存、诊断；结合当前会话定位。
- 模型配置：统一桌面连接配置入口，解决原生 DeepSeek 引导与桌面连接配置并存的困惑。
- 识图：独立 API 配置，支持 OpenAI Chat Completions 和 Anthropic Messages；在插件设置中配置，集成工具调用。

## 重复工作区引起的启动失败（2026-09-22）

用户提交的 `startup-report.json` 定位到随包 `dsh-workspace/lib/index.js:684`：同一个已规范化目录被两个工作区 ID 占用，原生注册表校验拒绝启动。这次诊断没有超时，也没有发生网络拦截。桌面旧连接历史迁移此前仅按工作区 ID 合并，未合并不同连接分别为同一目录生成的 ID，是本次修复的缺陷。

修正后的历史合并按 DSH 存储的规范化路径精确匹配，保留当前工作区的 ID、名称和排序，合并会话成员并保留归档集合。同一个 ID 指向不同路径时拒绝合并，避免错误归属。引擎启动前还会检查已经迁移完成的共享目录，将重复记录的原文件逐字备份到 `dsh/desktop-workspace-repairs/`，再原子写入合并结果；会话正文及附件文件不变，重复启动不重复修复。

`tests/workspace-recovery-wire.mjs` 使用真实原生 CLI 复现同一重复路径异常，然后验证桌面启动阶段自动备份修复、会话及归档成员保留、第二次启动成功。`tests/workspace-migration.mjs` 增加旧迁移标记、同 ID 会话合并、无 profiles 目录、冲突身份拒绝和幂等测试。用户实际数据将在新版启动时执行修复，本机隔离回归不等同于已经修改用户的失败环境。
