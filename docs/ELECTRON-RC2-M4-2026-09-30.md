# rc.2 适配、M4 迁移与后续开发决策

日期：2026-09-30。**rc.2 适配与 M4 已完成 Windows x64 个人联网候选的实现和本地验收。**内网现场验收继续暂缓；正式签名发行、干净机器安装和真实服务验收属于 M5。本记录替代旧计划中“下一阶段 M4”的状态，不改变 M0–M3 的历史验收记录。

## 官方基线与升级范围

当前固定基线为官方 [dsh-v0.2.0-rc.2](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.0-rc.2)，完整提交为 `639ed015397290b3745d163aafe02ffee4aa3f84`。本次核对时，Nidofy fork 的 master 与该提交一致。官方已提供 [Harness 桌面客户端](https://www.deepseek.com/harness/)，因此继续采用官方 Electron、Host、工作区和打包链路。

rc.1 到 rc.2 包含大量源码及生成文档变化，不能只替换版本号。本次在 `electron` checkout 的 `codex/rc2-m4` 分支重新应用已有迁移改动；原始改动另有恢复 stash，身份记录见 [origin.json](../electron/migration/m4/origin.json)。旧 Tauri、已有数据和 M1/M2/M3 候选均保留。没有创建提交、推送分支或发布 release。

| 变化面 | 本次处理 | 后续升级检查 |
|---|---|---|
| 官方 Electron、启动环境、打包依赖 | 合并 rc.2，保留独立 App ID、数据根、发行策略；M4 独立候选目录 | 官方启动、关闭协调、恢复入口、运行时文件与壳版本一致 |
| 官方模型目录 | 使用 rc.2 目录；测试不再依赖目录已移除的固定模型 ID | 按真实目录及连接声明验证能力，不沿用陈旧目录假设 |
| 连接及请求准备 | 保留不可变连接版本和凭据 lease；托管连接转发请求局部 payload hook | A 请求及其重试保留 A，新请求使用 B；撤销后不能发送 |
| 插件组合 | 自有配置 bundle 与功能 plugin 分成两个包 | 实际 Loader 能从 bundle 依赖发现插件，离线加载、卸载和重新加载 |
| 工作区及编辑器 | 沿用官方 UI 和 M3 窄桥 | 草稿 revision、会话目标、附件保留、官方 shell 执行 |
| 主题、字体、定时任务 | 复用 rc.2 官方服务 | 设置实时应用；内置 schedule 离线启用；旧任务不自动补跑 |

## 决定：官方能力优先，个人可选功能优先插件化

采用这个原则，但不将所有能力强行改造成用户可关闭的插件。官方本身以 Cordis 插件组合能力，自有功能接入服务、事件和客户端插槽，可以减少主引擎补丁；插件接口目前仍不稳定，插件化降低适配范围，并不能免除每次升级的测试。

| 功能 | 决定与当前归属 | 原因及退出条件 |
|---|---|---|
| Agent Loop、压缩、工具执行、Session 存储 | 官方独占 | 不维护第二引擎或第二份会话执行事实 |
| 登录入口、账号可选、更新策略、离线依赖、安装身份 | 发行组合与 Main 薄适配 | 决定产品启动和信任边界；不能依赖可选插件晚加载 |
| 多连接、独立凭据、热切换 | 独立 Host 模块及最小 provider seam | 属于核心能力；待官方提供等价事务、lease 和 ACK 后删除相应补丁 |
| 文件保护、原生命令准入 | 必需 Host owner + 原生 helper | 启用后失败必须阻断；不随个人扩展停用而失效 |
| 工程工作台、Git/Hg、构建、产物、任务投影 | 现有 M3 Host 模块及官方 UI/执行桥 | 后续有实际独立发布需要再拆包；本轮不冒险重写已验收链路 |
| 诊断、归档、A/B 比较 | M4 可选插件中的独立生命周期 | 默认关闭，只读采集失败不影响请求；本地脱敏、限额与卸载清理 |
| 缓存键策略、缓存实验 | M4 可选插件 + 一个请求局部 hook | 不修改 agent-loop；默认 native；只作用于允许的模型和本次 payload |
| 独立识图 | M4 可选工具和手动入口 | 走官方模型、附件和连接路径；不另存 Key，不另造 HTTP 客户端 |
| 桌宠 | 插件保存状态、投影任务与管理资源；Main 仅管理窗口与窄 IPC | 透明窗口需原生壳；任务和资源逻辑不进入 Main |
| 主题、字体 | 官方设置与插件 | 不移植旧 CSS 注入、DOM 猜测或重复主题系统 |
| 定时任务 | 官方 schedule bundle；个人插件只负责暂停导入与确认恢复 | 不保留第二调度器；历史任务不得自动执行 |
| CLI | 官方 CLI + 独立数据目录适配 | 任意 CLI profile 不自动具有 Desktop Host 的连接/保护能力，不能据此承诺与桌面全等价 |
| Antigravity/Google 订阅接入 | 单独评估，不混入 M4 | 不把普通 API 连接等同于第三方订阅额度授权 |

自有包为 `@nidofy/dsh-desktop-bundle` 与 `@nidofy/dsh-desktop-extras`。首次派生版启动登记 bundle；用户关闭或恢复时移除后，不在下一次启动强制加回。插件随完整发行物离线预装，尚未独立发布到 npm。诊断、缓存、视觉和桌宠各自默认关闭，启用失败显示不可用。完整插件停用后，连接和保护 owner 仍保留。

## M4 实际行为

“应用 → 个人扩展”提供中英文诊断、缓存、识图、桌宠、定时任务与自检六个页面。

诊断沿用旧报告投影和比较逻辑，采集官方请求及已提交工具事件。请求原文、凭据、原始模型别名与文件路径不进入共享报告。指纹采用进程内随机密钥；跨重载不能据此宣称请求相同。报告记录缺失覆盖，不将缺失缓存计数解释为零或缓存未命中。归档串行写入，并在卸载时等待完成。

缓存实验只发送合成文本，需要明确确认。预算为 512、2048 或 8192 个**估算输入 tokens**，四或六次请求，每次最多 64 个输出 tokens，限时两分钟。实验要求模型有已知上下文窗口且连接关闭自动重试；先冻结连接路由，再准备批次。取消会停止剩余预算。旧 bytes 预算保留原始单位并要求重选，绝不直接把 bytes 当 tokens。请求键支持 native、off、session；session 键按连接、模型、端点、数据根和会话隔离。探测延迟较低不能证明缓存命中。

识图选择独立连接及具备 image 能力的模型，通过官方 PreparedLlmCall 和附件服务发送一张图与问题，不携带主会话历史或工具列表。手动入口需要确认；Agent 入口为可选 `analyze_image` 工具。停用会移除工具并取消、等待未完成请求。自检区分本地检查和主动联网检查，不将未执行项显示为通过。

桌宠支持最多三个实例，每只拥有资源、位置、大小、任务固定、互动、目光、本地心情、安静模式和气泡配置。资源支持预览、摘要校验导入、明确替换、ZIP 导出与删除，内置资源只读。窗口只接受自身顶层 frame 的窄 IPC；任务状态来自官方 Session 查询及提交事件，不带任务文本和路径。冷读历史不触发完成通知；关闭功能销毁窗口并撤销监听。

定时任务使用官方 bundle。导入的是经过检查的 JSON 清单副本，源文件不变，全部标记暂停。用户选择已有根 Session 和新的未来规则后逐项恢复。恢复前先持久记录未知结果，避免中断后盲目重试导致重复任务；旧数据库不自动解释成新调度规则。

## 后续升级与开发流程

1. 从官方 release tag 建候选，记录 fork/upstream、lockfile、原生运行时、私有包和安装物摘要。不要跟随浮动 master 自动替换运行时。
2. 比较 `apps/desktop`、desktop-host、llm/provider、Session 查询事件、插件 Loader、客户端 workspace/composer、settings、schedule、附件和 shell 契约。
3. 对照 [补丁清单](../electron/migration/m4/patch-ledger.json) 逐项保留、调整或删除。先采用官方等价能力，再改自有插件，只有缺少正式扩展点时保留窄补丁。
4. 构建完整组合，先做类型、聚焦行为测试和官方文档检查，再运行带隔离数据的真实桌面验收。验证关闭个人插件后连接、保护和普通工作区仍可用。
5. 用旧数据副本进行升级演练。保留原候选、原数据和凭据绑定，不让新版和旧版同时写同一个活动目录。验证后由完整签名安装物发布，不热替换单个 node_modules。

新功能默认在自有插件里实现，必须声明服务依赖、数据 schema、模型可见内容、外发数据、取消和卸载行为，并补真实 Loader 组合验收。只有发行身份、OS 窗口、凭据及强制保护等宿主职责可以进入薄适配层。暂不为尚不存在的第二执行后端搭建通用框架。

本地模拟服务验收证明协议、路由、取消和生命周期行为，不证明真实服务的图片质量、计费缓存收益或企业出口限制。签名安装包、干净机器、多显示器与混合 DPI 长期体验、真实连接及内网网关验收继续留在 M5。
