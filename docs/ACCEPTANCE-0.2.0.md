# 0.2.0 持续现场验证

适用版本：0.2.0（旧 RC2 记录按原构建保留）。每次记录验证目录或包名，以及 BUILD_RECEIPT.json 的 id；ZIP 分发另记录 ZIP SHA-256。不同构建的结果分别记录。机器名称、内部地址、密钥、源码和原始日志无需写入共享结果。

按用户 2026-09-22 的指示，现场体验与开发并行；以下项目用于持续收集反馈，不作为本轮版本收尾的等待条件。本机构建、进程检查和交付完整性仍须通过。

## 环境与包

至少记录实际支持的 Windows 10 x64、Windows 11 x64 环境，以及实际外网服务、企业内网服务。缺少某环境时记 UNKNOWN，不能推断通过。干净目标机测试不依赖预装 Node/npm、Python、Rust 或 WebView2；工程本身需要的 Git/Hg、编译器和测试工具仍由工程环境提供。

1. 从同一候选包解压到用户拥有的本机目录，保留完整 resources。核对 ZIP 校验和；在企业允许运行脚本的环境执行 Verify-DSHDesktop.ps1，或使用本机自检检查运行时。策略拒绝时记录现象，不改变企业执行策略。
2. 启动并检查使用随包浏览器、默认界面和版本。保存一个测试连接，任务结束后切换。先执行本机自检并导出 JSON/Markdown；连接自检须确认界面显示的五次合成请求预算。
3. 在可丢弃的小型 Git 与 Hg 工程完成下面流程，再用实际工程执行日常任务。异常退出、断网、休眠和磁盘故障演练只在测试环境操作。

| 工作区环境 | 默认关闭，右上角打开 Codex 式浮动卡片；不展开右侧栏，正文与输入框不被遮挡；窄窗口自动收起，插件启停与主题切换生效；Git 分支、比较、暂存区提交及显式推送在可丢弃工程验收；Hg 状态和变更可查看 |

| 企业网络观察 | 由目标环境的网络观察验证实际访问范围；仅本机 HTTP mock 或 Node 拦截结果不能证明 WebView/OS 全局无出网 |

## 留下结果

可使用 evidence/acceptance-template-0.2.0.json 记录 PASS / FAIL / UNKNOWN / SKIPPED。PASS 应附操作与观察，FAIL 附最小重现步骤；SKIPPED 不等于完成。自检的两个现场项目会保持未知，它们不能由合成自检自行判为通过。

内部/外部服务分别记录所用 API 格式、模型是否一致、请求/输入/缓存读取计数覆盖情况及任务是否完成。比较缓存时使用同任务、同模型、同连接参数和相近运行条件，并同时检查正确性；不要求达到一个凭空设定的统一命中率。

分发时保留实际目录的第三方清单和许可文本，见 THIRD_PARTY_LICENSES.md。现场未验证项按计划持续跟踪，根据具体结果修复。
