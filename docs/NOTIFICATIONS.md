# 0.2.0 开发基线：后台任务提醒

入口：Help → 会话诊断 → 任务状态与恢复 → 后台任务系统提醒。默认开启，按连接独立保存；关闭诊断采集不影响提醒。偏好损坏时关闭提醒并提示重新保存。

| 原生事件 | 提醒 |
|---|---|
| 本轮 completed | 本轮任务已结束；不表示代码验收通过 |
| 本轮 error | 执行失败 |
| blocked / max-tokens | 任务需要处理 |
| approval/asked | 等待权限确认 |
| ask_user_question 调用 | 等待输入 |
| 用户取消、崩溃冷读、打开旧会话 | 静默 |

子任务结束不重复提醒；子任务等待输入或权限仍提醒。系统文案固定，不包含标题、工程路径、命令、问题正文、回答或服务错误内容。点击定位对应连接的原会话，没有自动发送或执行操作。

任何 DSH 桌面窗口位于前台时抑制弹出。被抑制、关闭期间发生、已消费的提醒不会在退到后台或重新开启后补发。等待被处理、新一轮开始或本轮结束会撤销相关旧提醒。引擎重启/切换销毁旧通知接收器，旧回调不能跳到新连接。

Windows 层使用 `Shell_NotifyIconW` 的通知区域提醒，独立隐藏图标绑定每次点击。保持现有托盘菜单，直接使用系统外观，无需联网、安装通知组件、创建启动脚本或开始菜单快捷方式。使用实时与静音标志并尊重系统 quiet time；API 成功只表示提交，不能据此认定用户已看到。参考 [Microsoft NOTIFYICONDATAW](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ns-shellapi-notifyicondataw)。

通知是临时提醒：最多保留 32 条、2 分钟，原生最多同时保留 4 个待处理图标；超过上限或 Windows 勿扰/企业策略抑制时不排队补发。原生记录与恢复页是核对状态的入口。应用退出后的点击激活、通知中心长期留存不在此实现范围。

验证：

- `tests/desktop-notifications.mjs`：等待解决、序号去重、过期、取消/子任务抑制、隐私边界、按连接持久偏好和损坏修复。
- `tests/desktop-client.mjs`：系统点击和恢复页导航共用经过验证的会话定位路径，迟到点击不覆盖新选择，加载不触发操作。
- Rust：前台/关闭抑制后不补发、重复轮询不重复提醒、身份验证。
- `tests/observability-wire.mjs`：两协议真实原生任务结束、采集关闭仍提醒、同源保护、偏好操作及重启/冷读静默。

仍待原生 Windows 10/11 验收：实际弹出、系统策略、点击恢复隐藏窗口、真实交互式权限/输入等待。上述本机逻辑回归与编译不能代替这些现场验证。
