# 0.1.4 — 每个模型的上下文和输出长度

0.1.3 的桌面配置生成器把所有模型的 `contextWindow` 写死为 32768、`maxTokens` 写死为 4096，因此原生 DSH 显示 32.8K。这不是对 GLM 服务容量的探测结果。模型 ID 又是原样发送的，`glm-5.3[1m]` 会作为完整 ID 请求接口，不能作为本客户端的容量开关。

0.1.4 在每个模型下面提供独立的上下文容量、最大输出和上下文快捷选项。1M 快捷选项表示 1,000,000 tokens，也可输入其他精确整数。请按实际服务限制设置；本客户端不能提高服务端限制，也不假设所有同名模型或内网代理有相同容量。最大输出必须大于零、小于上下文，上下文允许 1,024–100,000,000 tokens。

GLM 使用服务端支持的原模型名，例如 `glm-5.3` / `glm-5.3-flash`。对已有 `[1m]` 后缀，设置页显示“移除 [1m] 后缀并将上下文设为 1M”按钮，点击后才修改，避免静默改写自定义模型名。保存并重启后，在已有对话中重新选择有效模型或新建对话，容量统计在下一轮请求时更新。

配置保留原有 `models` 字符串列表，并新增 `modelLimits` 字典；旧单模型和多模型配置继续读取。缺少容量的模型保持 32768 / 4096 兼容回退值，设置页明确提示调整。容量设置在模型删除后随保存移除。密钥仍只保存到 Windows 凭据管理器。

```json
{
  "model": "glm-5.3",
  "models": ["glm-5.3", "glm-5.3-flash"],
  "modelLimits": {
    "glm-5.3": {"contextWindow": 1000000, "maxTokens": 16384},
    "glm-5.3-flash": {"contextWindow": 1000000, "maxTokens": 16384}
  }
}
```

上面是支持相应容量的服务的配置示例，不是模型规格声明。

## 验证

- 9 个 Rust release 测试通过，覆盖旧格式读取、容量序列化、整数/范围约束、失效模型引用及凭据隔离。
- 使用 Rust 生产代码生成的 overlay 启动未修改的官方 DSH，对 OpenAI 和 Anthropic 本地模拟接口分别执行真实流式对话与 read 工具调用。
- 断言模型请求 ID 保持 `glm-5.3` / `glm-5.3-flash`；最大输出分别为 16384 / 8192；原生 `request/context` 事件容量分别为 1000000 / 131072。切换模型、重启后续聊再次验证容量和输出参数。容量差异是回归测试夹具，不是 GLM 官方默认值。
- 设置页浏览器预览验证旧配置加载、后缀修正、自定义数值、1M 快捷选项、独立保存以及最大输出不小于上下文时阻止提交；使用模拟 IPC，不读写用户配置。见 `evidence/context014-settings.json`。
- 完整包保留内置 Node、WebView2、图标、背景和托盘。打包脚本运行离线 runtime 与 API 负面用例；提取最终 ZIP 后校验 WebView2 文件并运行桌面进程测试。

未调用用户 GLM 服务，也未发送百万 token 请求。真实服务上限和 Windows 10 目标环境仍需对应环境验证；工程验收状态继续保持 `DSH_DESKTOP_MVP_BLOCKED`。
