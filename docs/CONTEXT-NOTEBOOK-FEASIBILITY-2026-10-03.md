# 工作笔记与历史检索：附件审查和实施方案

审查日期：2026-10-03。对象：Electron 派生版的 dsh 0.2.0-rc.2 基线及本地插件组合。本文保留原始实施建议；后续 N0–N2 首版及 N3 初步评估的实际交付见[实施验收记录](CONTEXT-NOTEBOOK-IMPLEMENTATION-2026-10-03.md)，其中列明与建议的差异及尚未验证的事项。

## 结论

附件的主要方向可以实现：保留近期原文，用结构化工作笔记保存当前任务状态，需要细节时检索历史，并继续用官方压缩机制控制请求大小。建议作为私有插件组合开发，继续保持“个人功能优先通过插件实现”的原则。不要新建 Agent Loop、复制 Session 写入器，也不要删除官方紧急溢出恢复。

先做官方历史检索的启用与验证，再做只读可审阅的 Notebook，最后接入压缩摘要扩展接口。附件将一些“源码中存在”的能力当成了“当前桌面包已经开启”，还高估了增量笔记对信息失真的防护能力，这些需要修正。

附件里的 `chatgpt-content-reference` 标记没有可访问的原始链接。本次查到的 OpenAI 官方文档没有证实附件所述 Astra Notebook 内部架构；公开 API 文档描述的是不可直接解释的加密压缩项。因此可采用这个产品设计方向，但不应宣传为经过核实的“Astra 完整复刻”。参见 [OpenAI Compaction 文档](https://developers.openai.com/api/docs/guides/compaction)与[模型指南](https://developers.openai.com/api/docs/guides/latest-model)。

## 逐项核实

|---|---|---|
| 压缩后仍可读取旧事件 | Session 日志与活动上下文分离，查询支持 current、shadowed、log-only。压缩不等于删除日志，但用户删除、存储维护和制品过期仍可能使资料不可用 | 官方事件日志作为事实来源；不承诺无条件永久保存 |
| 官方已有跨会话引用 | `session-reference` 已在 Web 组合中挂载；捕获有界、只读、带来源的快照 | 复用原实现 |
| 需要新增 `@session` 输入 UI | `ui-reference` 已注册同时查找文件和会话的 `@` 来源，并写入 canonical mention | 先验证和补入口，不重复建设 |
| 五个历史工具可直接使用 | `tool-session-query` 源码有五个工具，但当前派生组合未挂载它们 | 增加依赖、离线打包闭包与 preset 装载，再做实包验证 |
| SQLite 全文搜索已经可用 | base 与 Web 的 `session-query-sqlite` 均配置 `openAt: never`；Web 使用 `:memory:`。精确读取与 trace 可以工作，不代表全文搜索开启 | 在私有 bundle 中完整覆盖配置，使用派生数据目录下的索引 |
| FTS5 + BM25 | 当前源码使用 FTS5 `unicode61`，查询按字面短语处理；排序为匹配次数、文档长度、时间等，并非 BM25 | 首版复用实际算法；中文、路径、报错串单独验证，不宣称语义搜索 |
| 不改 core 就能扩展压缩 | `ctx.compaction` 是可替换服务；`BasicCompactionEngine` 明确提供受保护的 `summarize()` 扩展方法 | 私有适配器继承官方实现，保留官方事务、取消和重放逻辑 |
| 在 compact 前挂一个 Notebook 更新钩子 | `compaction/start` 是事务中的同步日志追加；没有通用、可等待的“压缩前抽取”事件。`summary-error` 是失败恢复接口 | 首阶段独立笔记；需要保证顺序时接入 `summarize()`，不能依赖旁路异步监听 |
| Notebook 和 basic 两个 provider 同时作为回退 | 一个作用域中 `ctx.compaction` 只有一个服务所有者 | 回退在一个适配器内部完成，或切换 preset 配置；不同时挂载两个同名所有者 |
| 增量 KEEP/ADD/UPDATE/REMOVE 消除摘要漂移 | 能减少无必要重写，但遗漏、错误覆盖和累积偏差仍存在 | 增加版本、原文锚点、用户固定约束、冲突提示和长期任务评估 |
| 同项目会话天然可自动检索 | 模型工具的跨会话读取遵循 exact cwd；显式引用服务则假定 Host 已授权访问可见会话，并按目录亲和度排序。二者权限模型不同 | 自动检索首版保留 exact cwd；显式引用保持用户选择及来源提示 |
| 最近原文固定占 20–40% 即可 | 上限取决于实际路由、模型容量、工具定义、工具返回和输出预留 | 使用官方 token meter 与当前路由政策，比例只是可调策略，不作通用保证 |

## 建议架构

```text
官方 Session 事件日志 ── 官方 session-query ── 本地可重建 FTS 索引
          │                       │
          │                       ├─ 用户 @ 引用：固定的有界快照
          │                       └─ Agent 历史工具：受作用域限制的证据读取
          │
          └─ 私有 Notebook 服务：版本、增量、引用、冲突、预算
                       │
                       ├─ Desktop 笔记/来源 UI
                       └─ 私有摘要适配器 → 官方压缩事务与重放
```

Notebook 服务、UI 和压缩适配器分开维护。示例包名可用 `@nidofy/dsh-context-notebook`、`@nidofy/dsh-context-ui` 和 `@nidofy/dsh-compaction-notebook`；通过现有私有 bundle 控制启用、依赖和版本。历史检索优先直接使用官方工具，不在第一版额外暴露重复的 `context_recall`。若评估发现模型确实难以使用五个工具，再增加统一召回工具，并控制工具集合的重复与 token 开销。

索引存放在派生版数据目录内，由官方 SQLite provider 管理，是可删除重建的派生数据。笔记 Markdown 导出供人阅读；机器状态使用带 schema/version 的记录，不解析自由编辑 Markdown 作为权威状态。不要把模型每次请求时读到的“最新笔记数据库内容”直接塞进系统提示词，否则历史重放无法复现。

## Notebook 数据与更新

每个会话独立维护目标、约束、决定、涉及文件、验证结果、失败尝试、未解决事项和下一步。每条记录有稳定 ID、来源 Session/eventSeq、证据范围、更新时间、状态以及人工固定标记。测试结果必须区分“计划运行”“已运行通过”“失败”“尚未验证”；旧结果还应绑定当时的提交或文件状态，不能当成当前代码仍然通过。

更新请求读取固定事件截面，输出有界的结构化增量。服务校验条目和来源，按 `baseRevision` 做条件提交，产生不可变的新版本。REMOVE 表示当前工作集停用，审计版本保留；模型不能自动删除用户固定约束。互相矛盾的决定显示冲突，不能静默覆盖。每次只处理尚未纳入的原文事件，不把上一份摘要当成唯一证据。

首次可在回合结束后提取候选笔记，用户可以查看、固定和更正。后台提取与后续回合并发时，使用事件截面和版本检查；卸载、取消、路由切换后停止未完成提取，失败不推进已处理游标。笔记状态和事件截面必须在恢复时可核对，不能留下“游标前进但正文没写入”的状态。

模型可见的笔记快照、工具结果和修订依据都必须通过官方日志化输入机制进入 Session。外部缓存只做投影，重放读取日志里的那个版本。无需向官方 Session 格式随意添加必需的新事件类型；优先复用已有持久上下文和工具结果。如最终确需新事件，则单独评审兼容性和降级读取，不以插件可卸载推导旧客户端必然可重放。

## 压缩集成方式

第一阶段仍使用未替换的官方 basic compaction，Notebook 独立可见，不声称它必定在每次自动压缩前更新。

需要实现“先生成笔记，再形成压缩检查点”时，在私有 provider 中继承 `BasicCompactionEngine`，仅覆盖官方允许的 `summarize(input, agent, signal)`。输入使用该次压缩已经选定的截面，结果必须满足 `SummaryResult` 对安全文本、辅助模型调用和输出记录的完整要求。不能只返回一段自定义字符串，或额外调用模型却不记入辅助调用记录。

笔记新版本先作为候选；只有官方压缩成功提交并能对应到确切摘要/事件截面后，才成为当前有效版本。取消、会话变化或持久化失败时不能提前发布。可将版本内容和来源保存在官方已记录的摘要结果中，再由 Notebook 服务重建投影；跨文件提交若无法保证原子性，应采用可恢复的待提交/已提交标记，而非假定两次写入同时成功。

笔记生成失败时，适配器在同一次受控流程内调用官方原摘要实现回退；已经取消则直接取消。紧急 context-overflow 仍采用官方控制路径。标准、PTC 等实际可用 preset 分别验证作用域，防止只替换了一种会话模式。默认策略在回合边界切换，运行中不热替换 compaction 所有者。

## 检索、权限和内网

自动查找先查本会话被压缩的历史，再查 exact cwd 的其他会话。返回短片段、来源标题、Session ID、事件序号和是否已压缩；需要细节时按锚点精确读取。FTS 关闭、建索引失败、超时和没有命中是不同状态，UI 与模型工具不能全部显示为空结果。

用户显式 `@` 引用沿用官方快照：不会跟随源会话后续变化；主要为用户/助手文本与检查点，不是所有工具日志的无损复制。要核对旧测试输出，应通过事件检索读取原始工具证据。引用服务本身不是自动检索工具的权限替代品，自动召回不能绕过 exact cwd 限制调用它。

以后若支持 Workspace ID，必须先定义用户可管理的成员目录、路径规范化、大小写、符号链接和目录迁移规则，再调整授权。不能仅因两个路径互为父子目录就自动合并可读范围。检索到的旧指令和旧批准只作为资料，不授予当前会话权限。

第一版无需外部 embedding 或向量服务。本地索引可以离线运行，但生成笔记仍需所选模型连接；内网版应走用户配置的统一代理。索引在本机不等于历史内容永不离机：被选入提示词或模型工具结果的片段会发送至当前模型服务，产品说明需明确这一点。

## 分阶段实施和验收

| 阶段 | 交付 | 完成条件 |
|---|---|---|
| N0 官方能力启用 | 持久 FTS 配置、五工具依赖和 preset 挂载、现有 @ 引用实测、索引状态页 | 干净安装与断网启动；跨重启检索；压缩后仍能找到事件；exact cwd 隔离；中文/英文/路径/报错串夹具 |
| N1 工作笔记 | 版本化服务、增量提取、来源预览、人工固定/更正、日志化快照 | 取消/崩溃不丢有效版本；相同截面不重复更新；来源可读；回放得到相同笔记；停用插件仍能继续标准会话 |
| N2 压缩适配 | summarize 适配器、候选版本提交、basic 回退、按路由预算 | 压力触发/手动压缩/溢出恢复；工具调用边界完整；多次压缩后约束保持；模型失败/持久化失败/取消时不发布假检查点 |
| N3 召回优化 | 按需统一召回工具、检索评估、可选 Workspace 授权或本地 embedding | 在固定长期任务集上改善正确率/来源准确率；同时记录延迟、总 token、检索噪声和额外模型成本 |

每阶段均以真实 profile Loader 和打包后的 Windows 客户端验收，不只在源码里直接实例化插件。评估基线包含当前 basic compaction、只有检索、Notebook+检索三个组合；同一任务测试多次压缩后的目标保持、约束丢失、重复失败、错误跨会话召回和证据定位。没有结果前不承诺更省 token、更高缓存命中或消除遗忘。

## 跟随官方升级

维护一个明确的兼容范围，记录 session-query 请求/错误、session-reference 快照、SummaryResult、token meter 与各 preset 的装载结构。每次升级先运行官方普通模式，再运行插件启用、插件停用和老数据重放的契约测试。新增官方接口优先替换私有适配层；不要把官方内部文件复制到自己的压缩引擎里长期维护。

压缩适配器是最需要关注的兼容点。若官方改变 summarize 契约，先停止 Notebook 压缩策略并回到可验证的官方 provider，保留原日志与笔记版本，待适配通过再启用。SQLite 索引按官方 schema 迁移或重建；独立笔记格式采用自己的版本升级规则，不能用删除用户笔记来“修复兼容”。

## 本次范围

本次实际修改是环境卡片的详情和操作交互。Notebook、全文索引启用、跨会话工具挂载及压缩策略替换均为本文规划，未修改当前模型上下文流程。建议下一项开发从 N0 开始。
