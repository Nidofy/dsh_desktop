## Data and permissions

Native managed quota covers participating journals, not every project, Session, attachment, Shell spill or process allocation. Self-test UNKNOWN and missing counters remain unknown. Companion and pet attention follow a Session; they do not attest a T11 run or user acceptance. Optional analysis/model-assisted organization retain their own request and token costs; local pet coordination adds no model call or cache benefit. Closing pets leaves the companion, Notebook and notification owners available.

A private data root separates Chromium and Harness files but does not isolate Windows registration. Ordinary Main startup and personal sign-in retain their existing production scheme behavior. Explicit portable qualification suppresses registration and system command installation; observed production keys remain unchanged. Production-identity installers require a dedicated clean account/VM. Test-only installer identities qualify only their declared payload and installation scope. Private uninstall retains product data, package data and updater caches even without an inherited DSH_HOME; the corrected candidate is personal-unsigned-retain-data. Earlier unsafe Relay 28/29 installer outcomes remain historical evidence, not qualification of the current portable payload; old installer files were among the explicitly cleaned artifacts. See the [uninstall upgrade guide](../../docs/upgrade-guide/v0.2.0-rc.2/private-desktop-uninstall/guide.md).

Recovery uses the older program with pre-upgrade data; newer data have no in-place downgrade qualification. Raw Session and preference copies remain readable, but generation-bound Notebook sidecars reject changed physical file identities. The old Host recovered the untouched original physical files; full copied-Notebook or VM-snapshot recovery is unqualified. No real user data migration, signing, push, merge or publication occurred.

Two real project roots retain old S-1-4 grants without a verified original backup. The new mechanism refuses automatic relabeling on those trees; use a verified original backup or a reviewed new content-only workspace without copied security descriptors. No automatic repair or migration was performed. See the [ACL upgrade guide](../../docs/upgrade-guide/v0.2.0-rc.2/windows-acl-workspace-leases/guide.md).

The authorized cleanup removed 45 old artifact targets and reclaimed 62.594 GiB. p35f and p34f with their ZIPs, relay-35-final2 and failed relay-35-final remain; earlier evidence, scripts, worktrees and source assets remain. The cleanup plan and results are in ../.build/cleanup-20261013.
