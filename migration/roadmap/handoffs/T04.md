### 证据层次与实际缺口

Loader 测试执行的是**当前实际 v1 产品接线**，覆盖本轮 v1 隐式重试修复。v2 测试执行真实官方存储和真实 NotebookV2Store，但原事件/模型输出/request 日志是明确的协议 fixture，generation=17 只属于隔离试验；informational request fixture 经 public writer 带 ignorable:true 写入，以兼容尚未更新的 R catalog。没有改 KNOWN_SESSION_EVENT_TYPES、模拟 provider 成功、手填生产 generation 或私扫 Session 日志。此测试不是 v2 官方代次接线的端到端证明。

当前 `readActive` 不返回 cursors，官方 Session/query 也没有配对这次 raw prefix 的物理 generation；安装入口因此显式要求集成人员提供真实 `readState(sessionId, signal): NotebookV2`。这不是声称该官方接口已经存在。当前 catalog 未登记新增事件，入口明确抛 `NOTEBOOK_LOG_SCHEMA_REQUIRED`，不会用无法冷读取的未登记事件启动增强。没有同时装 v1/v2 消费者，也没有假装产品已经切 v2。T04 已提供消费者安装与提交逻辑，不等待 T03 再实现它们；仍缺的接口和公共产品入口归 R。

活动预算包含注入指令和完整 ActiveNotebookProjection；证据预算包含附录指令、已有 appendix、序号/游标/修订元数据和 JSON 转义，活动文本单独收费。整个新增 Notebook 附录不超过 maxActiveBytes + maxEvidenceBytes，不把近满活动集再次全部收费到证据额度导致无法增量。官方会话前缀、基础摘要指令和路由 token window 仍由官方引擎计量。delta 包含 JSON envelope、两个标签及实际原始空白；更新后的活动注入再次预检。maxHistoryBytes 保持 T03 对整个 v2 namespace 和临时替换峰值的计算，不删除旧记录换容量。

evidenceThrough 是顺序检查的完整原事件前缀；预算阻断处及后续事件不推进。非证据事件可检查后越过，注入笔记/压缩 checkpoint 不作新的原证据。commitThrough 将由成功持久化后的关联 end.seq 产生，与 evidenceThrough 大小关系无关；模型不能提供该值。
