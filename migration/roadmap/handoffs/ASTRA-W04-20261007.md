## 明确问题与复现

1. `packages/session/session-persistence/src/index.ts: SessionPersistenceSnapshot` 没有物理代次；opaque revision 仅限同 provider 实例和 Session id 内比较，不能持久充当跨冷启动 Notebook scope 身份。
2. `packages/session/session-persistence/src/handle.ts: SessionHandle.read` 允许观察 best-effort append；只有 flush 保证持久。`desktop-extras/src/notebook-commit.ts: readNotebookDurableEvents` 先 flush live Session，再另开 read，却不知道返回前缀中哪段获该 barrier 确认，也没有与事件配对的 physical generation。
3. 单文件探针 `migration/roadmap/probes/w04-durable-prefix.spec.ts` 用真实 JSONL 保存 durable seq=0；明确标注的 buffered read override 只模拟公共接口允许的 barrier 后可见性。flush 成功后新增的 seq=1 未获 durable acknowledgement，当前 reader 却返回 `[0,1]`，预期 `[0]`。命令：`node node_modules/vitest/vitest.mjs run --config migration/roadmap/probes/w04.config.ts migration/roadmap/probes/w04-durable-prefix.spec.ts`。exit 1，1/1 失败；日志 `.build/dispatch/evidence/relay-01/durable-prefix-probe.log`。这是公共语义/消费者问题；真实 JSONL 的 appendLines 调用 handle.sync，不把此模拟说成 JSONL 未 fsync。
4. `NotebookScope.generation` 仍是 number；`commitNotebookCompaction` 只比较 Notebook revision，未校对持久事件的官方 generation。协议 fixture 的 17、header.version、缓存 revision 均不能补缺。context/config/Panel/工具仍消费 v1，未调用 v2 installer。
5. JSONL read 可从历史物理代返回迁移后的 current logical events，write open 再发布格式 successor。身份如何绑定 read-selected 原代、迁移新代、fork/恢复和 Notebook 旧证据，现有约定没有唯一回答。代次变化须使 admission 等待中的候选失效；单次 stat 检查不能关闭此窗口。
