## 已完成的相邻准备

- [generation.ts](../../../packages/session/session-persistence-jsonl/src/generation.ts) 的 `PreparedJsonlMigration.measure` 用实际 raw/zstd 编码计算后继字节，不写暂存文件；`publish` 在每次文件写入前检查 `maxWriteBytes`。源副本、调用方元数据、解码内存不在该值内。测量后的编码增大也会在写入前拒绝。

1. 定义 sibling imports 的真实物理根准入：由现有 home 的同一 native ledger 验证并授权精确 import 目标，或另一项明确保留同一物理发行根的方案。不能放宽 Node 相对路径检查就称原生身份资格；不能由 imported home 开第二份 ledger，不能用进程内 Map 当跨 Host 授权。原 ordinary/terminal、磁盘余量及实际排空规则保持。
2. 定义产品 import operation 与 quota grants 的持久化关系及提交点，涵盖协调锁、清单复制、转换 stage、JSON 原子替换、final rename 的实际峰值。可按操作保留整次额度或按阶段准入，但必须可查询并恢复，覆盖 child／worker 排空、取消、ACK 丢失、崩溃和已有 pending/final 树。callback 返回失败或重启后看到部分文件不能自动重放未知副作用；普通 atomic rename 不是新增断电回执。无界 takeover residue 也不能被预算遗漏。
3. 决定并实现显式 adoption 的持久格式与恢复：保持 import home 原位并由现有根管理，或明确搬到发行根 sibling home 后接纳。两者对 home 绑定、quota owner、imports 计量和普通 Session/attachment 排除项有不同后果；必须明确一次计量且不能因目录分类切换悄悄消失。移动后 patch 的绝对 Session root 也需要有明确、可恢复的更新。原物理 journal、import 和历史 Session generation 均不能自动重绑／覆盖／删除。
4. 接消费者与认证 preview/execute/inspect/adopt UI，只有满足上述准入和恢复资格后才解除执行拒绝。保留无秘密／无可执行插件、工作区重新确认信任、计划不自动激活和 Notebook 新物理 scope 不自动重绑。改变 native 持久格式时更新真实 schema／serde 和兼容策略；不造 Session acknowledgement。
