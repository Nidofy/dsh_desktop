# 任务交付模板

复制本模板到 `migration/roadmap/handoffs/Txx.md`。每个任务独占自己的文件；评审结论另存审查记录，不能让作者给自己盖最终通过。

## 身份

- 任务 ID / 本次交付单元：
- 作者模型、入口与推理设置：
- worktree / 分支：
- 实际代码状态（相关实现、配置、未提交及未跟踪改动）：
- 前置任务与实际已就绪能力：
- 变更文件范围（提交记录可选）：
- 作者状态：READY_FOR_REVIEW / PARTIAL / DEPENDENCY_BLOCKED / ENVIRONMENT_BLOCKED
- 当前范围与明确后置：

## 实际改动

列出文件、具体行为及原因；注明公共接口是否变化、所有消费者是否已接线。缺少依赖接线时明确列出文件与最小所需修改。

## 验收证据

| 要求 | 命令或操作 | 被测目录与实际代码状态 | 退出码/结果 | 证据路径 | 覆盖限制 |
|---|---|---|---|---|---|

保留失败与修复后的结果，说明未执行项。日志不可含秘密。性能给出机器、数据量和测量口径；不要仅附一张 PASS 截图。

## 数据与恢复

记录 schema 变化、旧数据保留、迁移原子性、中断后的恢复步骤、回退所需副本及不能支持的降级路径。

## 生命周期与接口

记录请求/监听器/子进程/配额的唯一所有者、取消与卸载、重复操作、丢 ACK、并发冲突和已知残余风险。

## 交给审查者

用一段话说明最需要检查的逻辑和最短复现步骤；附未决问题，不以“已全面验证”省略范围。
