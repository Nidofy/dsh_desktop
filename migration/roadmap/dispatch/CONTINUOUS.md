## 持续推进

循环执行：选择最近的可交付行为→实现与所有消费者接线→运行受影响验证→修复→简短记录→选择下一项。完成一个 Txx、一个提交、一次测试或旧阶段门槛不是停点。依赖缺口若可在现有架构下明确补齐，由当棒直接完成。

当前目标为功能完善与本地便携使用，优先顺序和完成条件由 [NEXT_PROMPT](NEXT_PROMPT.txt) 指定：T21 侧边分析 → T22 有限自然语言设置 → T16 及主要用户流程在便携包中的完善 → 可实施的 T15 → 必要便携启动入口与 T26 本地说明。T21/T22 纳入开发范围，产品能力仍由用户显式启用；单项外部阻塞时继续其他功能。

生产身份安装/卸载、NSIS、正式协议、旧安装替换、完整物理恢复、干净机、真实休眠、混合 DPI、企业现场、签名及发行许可认证不属于当前阶段完成条件。历史资格原样保留为延期项，不是功能开发的全局阻塞。T24 当前只承担便携目录/ZIP、必要 EXE 启动器和实际功能验证；不会因便携交付自动触发新的发行审查。真实数据保护、必要依赖使用条件、产品权限和日志兼容义务仍有效。

每个单元开工只列少量可观察的完成条件，随后直接实施所有必要消费者并验证；条件满足即进入下一就绪单元。PARTIAL 可以表示明确剩余资格，不是所有后续工作的阻塞。完整资源峰值、极端环境或真实提供方资格只有在任务承诺或具体缺陷要求时才成为当前前置；不得用检查点冒称峰值、降低要求或隐瞒未知。对无法保证的能力准确说明或拒绝启用，同时推进独立功能。

提速以完成用户可使用的行为为准。禁止将泛化审计、反复盘点、重写历史证据、无相关变化的重测和台账整理替代实现；不设额外独立 review/integration。普通缺少实现、接线或登记由当棒补齐。文档随对应功能更新，历史细节保留链接，不为资料完整性另开一棒。

当前作者可更新实际涉及的 registry、ownership 和 tasks 条目及必要共享配置、构建和消费者；保留无关内容，只因实际依赖变更修改锁文件。旧单棒“仅 T20 可改”和其他局部冻结安排不限制后继任务开发，历史字节断言只说明当时验证结果。此授权不修改既有数据、权限、日志兼容或真实验收义务。

## 何时交给 Astra

具体触发之一即可，需写明文件、失败行为与所需决定；不能只写“任务复杂”：
1. 需要改变持久化公共语义、日志代次/连续前缀、提交恢复或向后兼容，已有约定不足以唯一决定实现。目前 W04 的 physical generation + raw durable prefix 是已识别实例；先核查它是否已被解决。
2. 凭据隔离/迁移、权限扩大、原生清理/恢复等存在未验证的高风险不变量。T02 在把 provider 作为产品默认启用或涉及真实数据前，合并一次定向安全检查；Sol 可先完成包注册与隔离 profile 验证。此前相同实现已经过 Astra 确认时不重复开审。
3. 同一根因两轮有证据的修复仍失败，需要重新决定方案。提供最小复现和已排除项。
4. 明确业务需求冲突或多个不可兼容设计，需要跨模块裁决。

正式发行已延期，首包/安装资格不再触发交接。Relay29 已完成的决定沿用；本地便携入口由 Sol 实现，仅新的具体数据或权限冲突按上述条件交 Astra。

普通类型错误、lint、冲突、注册缺失、测试适配、UI 接线、生成 catalog 和文档登记由 Sol 自行解决。G-A 至 G-F 保留为验收清单，纳入当棒测试；没有理由不再单独创建审查/集成会话。涉及 required 日志事件时先定兼容性策略，再生成真实 catalog/acknowledgement，不能删 guard 或降低验证来通过。

## 交接最小集合

每棒结束时只要求：
1. 更新本目录 `NEXT_HANDOFF.md`：当前工作目录、实际完成/未完成、运行命令与结果、代码/数据风险、下一步、接棒模型及具体原因。写本棒增量及下一单元完成条件；历史细节引用原记录，不逐棒复制整段历史。
2. 更新 `NEXT_PROMPT.txt`：可直接发给下一模型的完整启动文字，写明绝对工作目录、需读文件、第一项动作、完成/转交条件；已有已解决 Astra 问题不得原样重复交回。
3. 在 `../handoffs/relay-NN-sol.md` 或 `relay-NN-astra.md` 保存本棒简短记录，包含发出的下一棒 prompt 或其当时副本。最终聊天也贴出同一 prompt，便于人工切换。

模型由用户在 Codex 选择；文件不会自动切模型，也不会在会话结束后自动后台运行。不默认创建新聊天、代理或定时器。Txx handoff/registry 只在涉及的任务状态发生实质变化时更新，不能为报表另开一个开发阶段。历史审查保持原文。

## 测试与完成
