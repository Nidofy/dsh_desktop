## Select and compare

Open **Compare task receipts** from the engineering workbench's **Build and test** page. Enter an existing workspace, load retained receipts, select A and B, and choose Notebook or cache as the requested factor. Reading creates no directory, ticket, provider call or execution. The page creates explicit experiment/case grouping IDs; those labels do not attest that the runs share a task or actually used different factor settings.

The reader calls the actual [VerificationOwner](../workbench/verification.ts) for each exact canonical workspace/run reference. It compares committed identities, intent, source/input fingerprints, execution configuration, input coverage, current freshness and log availability. Configuration revisions are comparable only within one workspace. A known difference, a stale result or the same execution selected twice rejects direct task comparison. Unavailable observations remain unknown. Parsed tests, acceptance and freshness remain separate; two accepted runs do not establish equal quality.

The table links each selected original run to its retained receipt and shows each count's missing-side total. Parsed test counts come only from complete available T11 logs, independently per side. Model calls, input/output tokens and cache-read tokens are null with two missing sides because T11 does not own these measurements. Matching receipt inputs do not establish complete task comparability or an efficiency improvement. A complete comparison above 64 KiB refuses without cropping or archiving it.

**Inspect selecting model step A/B** reads private evidence only after an explicit action. The original T11 source restricts the Session; a unique committed `run_project_action` result, matching receipt and call identity establish its selecting turn/step. The official durable reader and physical-generation guard reconstruct each settled attempt's complete logged history, call configuration and tool declarations with the actual registered message interpreters. The view retains raw text and may contain sensitive task content. It does not send, flush, repair or publish a Session. Desktop runs, inherited results, missing or ambiguous links remain unknown. Scanning refuses over 4,096 events or 2 MiB after the official read; the full response refuses over 64 KiB without cropping.

Step usage comes from the official embedded stream, including settled failed attempts. Each token counter remains null if any attempt omits it; explicit zero remains zero. These counters cover only the step that selected the action, not the entire task or every provider wire request. Historical logs do not retain the dispatch cut, so a reconstructed pre-settlement prefix is labelled separately from the unobserved actual dispatch input. Each attempt reads a provider-reported model from supported official finish replay metadata matching its requested route/model; absent or unsupported metadata stays unobserved. Neither that reported identifier nor the requested alias attests an immutable model version. Historical Notebook/cache policy remains unknown; present preferences and note text do not attest those settings. These reads do not change the comparison table or the schema-version-1 selection checkpoints.

<a id="records-and-import"></a>
## Records and import

**Save selection record** commits a separate schema-version-1 `receipt-task-comparison` record under `nidofy-extras/experiments/records-v1`. The record retains grouping/run references, time and small receipt checkpoints, including independent acceptance revisions. Reads show both the saved checkpoint and newly inspected facts, with an explicit change indicator. They never rewrite a saved record or reconstruct an unfinished receipt. An unknown save response retains its caller-generated identity across page reload; explicit inspection does not automatically resubmit a missing record.

Complete UTF-8 JSON is limited to 64 KiB per record and twenty retained records. The directory allows eighty entries and `22 × 64 KiB + 4 KiB` total bytes including lock and temporary residue; admission includes publication peak space. The existing native distribution quota covers lock metadata and exclusive synchronized publication. Capacity, damage, links or unsupported versions refuse further writes and preserve original bytes. Records are not automatically pruned. Host unload cancels unpublished operations and drains all current reads/writers before T11 closes; cancellation after publication does not negate a committed record.

Export produces private selection JSON containing workspace paths and receipt identities. It contains no model body or credentials and is not a redacted diagnostic export. Import checks full size, version, allowed fields, source classification and identities, then independently reads both local committed T11 receipts. Canonical selections and every checkpoint must match current observations; a source string alone is never trusted. Foreign, changed, forged, legacy or unfinished evidence refuses without task execution, model sending or automatic repair. An existing record ID refuses replacement; inspect it instead. Old diagnostic/Probe reports are not imported or silently upgraded.

<a id="single-task-request"></a>
## Single task request

The same page offers an independent **Single task request** for private analysis text. Select a managed connection/model, enter the complete text and output-token budget, optionally select an explicit Notebook source Session, and preview the complete task, committed note input, physical generation, note/settings revisions and rendering limits. Preparation does not flush or synchronize the source, read credentials, allocate a journal or send; missing ownership refuses the selected input. Confirm the displayed input and revisions to authorize exactly one request with zero provider retries, at most 8,192 output tokens and a three-minute lifetime. This request has no tools, Agent, project writes or receipt. Its grouping labels do not establish a common acceptance task. An unconfirmed start retains its run identity across reload; read it explicitly rather than resubmitting. Cancel waits for the provider and writers to drain. Closing the page cancels an unconfirmed preview read without cancelling committed work.

The [task owner](task-requests.ts) rechecks the actual managed connection revision, separate T23 HTTP lease and selected Notebook capture before sending. Changed source generations or note/settings revisions refuse instead of silently refreshing confirmed content. The [input journal](task-inputs.ts) writes the full header and private text, with the note input in a separate text block prefixed by two newlines, through the official Session writer, flushes, cold-reads and reconstructs the request, then commits its exact prefix cut and invokes the bound prepared call under the same physical generation. `preparedInput` is retained independently; `dispatchInput` requires a committed terminal observation that the stream was invoked. A process loss between preparation and terminal publication stays INTERRUPTED with unknown dispatch count. The cut identifies the Harness request passed to the prepared call, before provider wire projection; it does not attest exact wire bytes or a provider wire-call count. Explicit note inclusion is not a complete Agent prompt assembly or an engineering-task factor experiment.

Each request uses a fresh independent schema-version-1 journal under `nidofy-extras/experiments/task-requests-v1`. Complete text is limited to 16 KiB, captured streams to 2,048 chunks and 24 KiB, complete read responses to 64 KiB, and retained root bytes to 256 KiB including publication peak. Admission allows twenty roots, ten unfinished roots, eighty entries per root and `22 × 256 KiB + 4 KiB` total directory bytes including admission locks. Native ordinary and independent terminal allowances cover each writer. Unknown residue, links, hardlinks, damaged or future records refuse without pruning. Output refusal or cancellation retains an explicitly incomplete stream when it fits; an unconfirmed terminal commit stays interrupted. Reads never repair a journal or resend.

Independent schema-version-1 `notebook-input.json` and `execution-observation.json` sidecars retain the optional source capture, actual applied Desktop cache hint, captured preference revision and official response-model identifier. The identifier must match the cold-read official stream; the observer retains no cache key or credential. Admission validates retained sidecars and refuses unknown root residue. Old journals remain readable without sidecars and gain no fabricated historical observation. An unconfirmed terminal does not attest an applied factor; an absent transform stays unknown. Native/removal/session-key facts describe routing hints, not provider cache enablement or hits.

Counts come from the official captured stream. Missing counters remain null, including a zero value omitted by an adapter; explicit reported zero remains zero. Input and cache-read counters retain their official meanings without recomputing them from wire prompt totals. This request retains explicit Notebook input and applied cache-routing observations; provider cache behavior and exact model version remain unknown. Quality, receipt association and task A/B efficiency remain unqualified. The original comparison table, selection records, T11 receipts and T19 reports retain their independent semantics.

## Isolated engineering task

**Isolated engineering task** previews an explicit complete relative input closure, locally trusted build/test actions, the full task text and an independent request/output/tool/action/time budget. Experiment and case UUIDs can be reused across explicitly confirmed factor trials; blank fields generate local labels once, and edited labels invalidate the preview. Labels alone never establish common inputs. Confirmation creates a fresh retained workspace copy and one official Agent turn. The Agent can only list selected actions and execute reviewed IDs; it cannot supply shell commands, use PTC, change settings or accept receipts. The copied configuration gains trust only from this explicit confirmation. Source trust/configuration, the managed connection revision and the actual T23 lease are rechecked before requests and action bodies. Changed confirmation inputs refuse; failed and unknown outcomes do not retry or fail over. Full-access profiles refuse preparation, and the actual Session sandbox mode and copied workspace boundary are rechecked before requests and action bodies; read-only remains read-only.

The [copy owner](project-copy.ts) reads every selected file, including dirty, untracked and binary inputs. It refuses links, hardlinks, overlapping roots, VCS metadata, traversal and Windows path aliases. Physical identities and complete bytes are checked before and after copying into an exclusive destination. Limits are 512 entries, 16 MiB total and 1 MiB per file. They cover the selected incoming closure, not all later reviewed-action outputs. Partial copies and original sources remain retained on failure; source files are not overwritten.

Directory preview uses bounded iteration and retains only names within the remaining entry allowance before sorting; nesting beyond 128 selected levels refuses. Exact-limit closures keep the same sorted observations and fingerprints. A refused enumeration returns no partial preview and allocates no destination.

The separate [resource owner](engineering-resources.ts) requires an explicit `resourceBudget` in every new engineering preview, including matrix rows. `workspaceBytes` and `workspaceEntries` cover the entire copied project, including later outputs; `retainedWorkspaceBytes` charges every retained allocation's full workspace ceiling before creating another copy. Those charges are not refunded after a run. Limits allow up to 128 MiB and 4,096 entries per project and 512 MiB of retained workspace ceilings. Admission checks existing physical allocation owners and complete current file lengths; an old journal without an allocation remains readable with unknown resources but refuses new resource admission. Changed identities, links, hardlinks, inaccessible trees and incomplete enumeration refuse without deleting or cropping evidence.

The independent [Shell observer](engineering-shell.ts) requires explicit `shellBudget.outputBytes` and `shellBudget.retainedSpillBytes`. It reads whole-stream byte coordinates from the actual Workbench handle after settlement, independently of bounded tail text, and verifies available spill file identities and lengths. Exhausted or unknown observations refuse subsequent requests/actions while preserving the original action result and T11 receipt. Each retained run keeps at least its full output allowance charged; larger observed output or actual spills increase the conservative charge. Truncation without an available spill or failed spill measurement leaves retention unknown; independently known complete output coordinates survive that refusal, and comparison never displays unknown spill capacity as zero. Missing historical Shell owners or changed/inaccessible spill files refuse new admission without deletion, adoption or replay. Limits permit 64 MiB output per run and 512 MiB retained spill charges. The native journal quota does not cover these files; action-time disk growth and decoded/Host memory peaks remain unknown.

`sessionBytes`, `sessionDiskBytes` and `sessionEvents` separately bound the complete logical durable snapshot, the actual official `stat().sizeBytes` observation and the event count, up to 2 MiB, 2 MiB and 4,096. Request checkpoints flush and observe the official writer, then read physical length under the same generation before prepared dispatch. Missing physical length refuses; it is never zero. Copy checks run before requests, before and after tool bodies, and after drainage. An oversized action output preserves its real T11 facts and copied files while preventing subsequent work. Independent schema-version-1 allocation/result sidecars retain the original limits and successful or refused checkpoints. Cold reads revalidate logical Session prefixes and the drained physical length; comparison displays drained bytes separately from turn counters and missing-side totals. These are cooperative checkpoint limits: action-time disk growth, action-time spill growth, allocation overhead, decoded Session memory and Host memory peaks remain unqualified. The native managed journal quota does not cover them.

Every engineering Session read checks actual physical metadata before `observeDurable`; absent length or a physical limit violation refuses before full decoding. Complete logical size and event limits are checked before constructing detached Sessions, and changed metadata revisions refuse. Cold journal reads use the existing 2 MiB/4,096-event scan envelope, including runs that refused smaller confirmed checkpoint limits. All input cuts, settlements and resource observations share one complete official observation and one generation guard per read; resource sidecars with no request cut still revalidate their original prefixes and drained watermarks. These are operation-local observations, never a cache across reads. A small compressed artifact can expand beyond the logical limit inside the official decoder; its allocation and clone peak remain unknown.

The [budget owner](engineering-budget.ts) allows at most eight requests, 8,192 output tokens per request, 65,536 allocated output tokens, sixteen tool bodies, four action attempts and three minutes. Every field must be explicit. Each dispatch reserves its entire output ceiling; unused output does not refund permission. An action ID runs at most once. Missing output usage, failed/unconfirmed action receipts, permission denial, exhausted budgets and cancellation prevent further work. Official missing token counters stay null and explicit zero stays zero. Counts cover admitted prepared-call entries for the independently owned turn; a refused earlier stream entry is not a dispatch; provider wire counts and immutable model versions remain unobserved.

The [input capture](engineering-inputs.ts) runs after the official checkpoint listener. It flushes the actual Session writer, cold-reads the complete prefix with registered message projections, compares the complete request, publishes its cut and enters the original registration-bound stream under that physical generation. Inputs refuse over 128 KiB; streams refuse over 2,048 chunks or 24 KiB without cropping. The stream drains under the generation before its bounded chunks return to the Agent. Official finish and usage reach the normal Agent settlement even when the budget refuses subsequent work. Nested or unrelated calls gain no run permission.

Independent schema-version-1 records live under `nidofy-extras/experiments/engineering-v1`; existing analysis, comparison, T11, T19 and Session formats stay unchanged. Exclusive publication uses the existing native quota with independent 2 MiB ordinary and 1 MiB terminal allowances. Admission permits twenty roots, ten unfinished roots, eighty entries per root and `22 × 2 MiB + 4 KiB` total record bytes, including locks; each root permits 2 MiB including publication peak. Copies are retained outside the application home with separate incoming-file limits; this journal quota does not qualify their later outputs or official Session memory/disk peaks. Full reads refuse over 1 MiB. Active reads expose RUNNING with unknown counts; only a terminal record attests dispatch observations after Agent/provider/quota drainage. Cold reads validate full inputs against the official generation and observations against official settlements. Missing terminals stay INTERRUPTED with unknown counts and never resume or resend.

Engineering and matrix journal listings use bounded iteration before collecting names, including unknown lock or temporary residue. Capacity refusal retains each owner's existing diagnostic. Recursive engineering journal size checks also iterate within their complete entry ceiling. Already-admitted terminal writers continue their scan and publication after read cancellation so their original drainage obligation remains intact.

A receipt link requires the actual unique official `run_project_action` call/result, call identity, matching T11 receipt and original execution source. A Session label does not establish an action. Tests, freshness and local-user acceptance remain independent. Optional Notebook and cache inputs are retained separately; observed cache hints do not attest provider caching. Unknown starts retain their identity across reload for explicit reading. Closing the page aborts its HTTP/read lifetime; explicit cancellation stops owned copy/Agent/action work and drains it.

An explicit Notebook source reads the actual owner without synchronizing, flushing, converting or writing that source. Its complete text is appended as a separate User block. Source generation, note/settings revisions and limits are rechecked before dispatch and action bodies. The optional schema-version-1 `notebook-input.json` retains that original capture. Optional cache selection confirms the actual `nidofyCacheInput` owner, enabled/mounted state, preference revision and current policy; it never changes global preferences. The independent `cache-input.json` capture must match the subsequently applied payload observation. Missing old sidecars remain unobserved, and present settings never fill historical fields.

**Compare retained engineering turns** reads original run IDs through the engineering owner. Its separate [comparison](engineering-comparison.ts) shows complete prepared inputs, original intent/terminal times and configuration, observed provider-reported identifiers, copied input closure, Notebook/cache captures and current causal T11 receipts. Different task/code/input/model/configuration or full context rejects direct comparison; every model-visible field is retained, with Session identity separated as the run locator. The table reports whole-turn prepared dispatches, official usage and missing-side counts, with explicit original-journal buttons and exact protected-receipt links. Input and cache-read tokens remain separate. Failed settled counters remain observed; missing counters are never inferred from receipts. Independent dual acceptance is only BOTH_ACCEPTED, exact immutable versions remain null and efficiencyEligible stays false. This read neither accepts receipts nor changes the old comparison table or records-v1.

<a id="bounded-matrix"></a>
## Bounded matrix

The [matrix owner](engineering-matrix.ts) previews two to four engineering rows with the same experiment, case and task text. Explicit aggregate ceilings allow at most 32 requests, 262,144 allocated output tokens and 60 seconds. Each row reserves its complete request/output ceilings before admission, executes sequentially in a fresh copy and archives its drained status, counters and original receipt references. Failure, uncertainty, timeout or cancellation prevents later rows. Cancellation retains the drained current round. Current settings are revalidated per row; different cache modes require separate explicitly confirmed trials.

Independent schema-version-1 records use `nidofy-extras/experiments/matrices-v1`: at most twenty roots, ten unfinished roots, sixteen files and 2 MiB including publication peak per root, with `22 × 2 MiB + 4 KiB` directory admission and native 2 MiB ordinary/1 MiB terminal grants. Reads revalidate complete original previews, contiguous rounds and their engineering journals. Official generation reads are serialized within the engineering owner; a read snapshot retains its running state through terminal publication. Full reads and reports refuse over 1 MiB. Completed aggregates require every round's complete counter; otherwise they remain null. Provider wire counts remain null, quality UNKNOWN and efficiencyEligible false.

**Export original matrix report** retains only the original intent, rounds and terminal with the source identity and start time. **Validate report against this journal** checks version, size and exact retained source before returning a read. It creates no task, writes no imported journal and never repairs or replays a missing source. Cold reads and imports preserve original bytes.

<a id="implementation"></a>
## Implementation

[TaskComparisonOwner](owner.ts) is a Workbench-owned reader and archive consumer, with a separate task-request delegate. The existing authenticated connection dispatcher serves `/api/nidofy/workbench/experiments/ui` and `experiments/compare`, `record`, `list`, `read`, `import`, `task-prepare`, `task-start`, `task-read`, `task-cancel` and the independent `engineering-prepare`, `engineering-start`, `engineering-read`, `engineering-cancel`, `engineering-compare` and `matrix-prepare`, `matrix-start`, `matrix-read`, `matrix-cancel`, `matrix-export`, `matrix-import`. Only the local-user HTTP path exposes these operations; there is no model tool or alternate application launcher. Each operation refuses unrelated fields. Read-only comparison remains available in repair compositions without storage; archiving and task requests refuse when their required owners are unavailable.

[Comparison](comparison.ts) projects actual T11 facts, [records](records.ts) validates the independent archive format, [model lineage](model-lineage.ts) reads exact selecting-step evidence, and [UI](ui.ts) owns bilingual presentation and late-result rejection. The authenticated `experiments/model-step` operation accepts only a selection and side. The reader does not consume the old cache Probe's sending path or infer task identities from diagnostic archives. Built-profile evidence and remaining qualification belong in the [Desktop tests reference](../../../desktop/tests/README.md#verification-experiments).

<a id="known-limitations"></a>
## Known limitations

The bounded matrix does not certify general Agent-task billing, real-model quality or A/B efficiency. The separate one-request analysis journal does not make selected T11 tasks comparable. Historical dispatch inputs, Notebook/cache settings and exact model versions remain unobserved. Nested PTC dispatches have no direct `run_project_action` result and remain unknown. T19 fixed self-test inputs are not reused as task A/B evidence. Sandbox Shell enumeration can keep T11 coverage unknown even after real TAP tests pass. Receipt workspaces must remain reachable. Installed renderer, physical crashes and hostile concurrent filesystem replacement remain unqualified; reads grant no repair or deletion permission.
