# 项目验证与通知

[English](README.md) | 中文

## 概述

运行本地审阅过的项目动作，读取其保留验证回执，并记录独立验收决定。命令退出、解析的测试、输入覆盖与当前输入新鲜度分别判定。工作台关闭时，新回执通知仍使用同一持久身份。

工作台为[正式隔离自检](../selftest/README.zh.md)提供同一 Shell 权限下的固定执行。该 owner 保留有界报告，不将用户 Session 结束解释为测试资格。

[任务回执比较](../experiments/README.zh.md)读取显式 A/B 运行选择，并保留有界私密记录。独立读取方还使用原始 T11 执行来源与官方工具结果检查选择动作的模型 step。缺失任务计数仍保持未知；读取方不启动任务，也不从旧诊断推断因素设置。

同一页面提供单独确认的[单次分析请求](../experiments/README.zh.md#single-task-request)，拥有独立预算和官方输入日志。它没有工具、Agent 或工程写入，不复用 T19 确认。回执比较、任务质量和因素等价仍独立且未资格化。

<a id="verification-inputs"></a>
## 验证输入

动作的可选 `verification` 对象使用 schema 版本 1，提供 `intent`、`parser`、`coverage`、`sources`、`inputs`、`toolchain`，以及用于算例或容差的标量 `parameters`。本地用户将这些字段与命令一起审阅，再信任所得配置。`sources` 与 `inputs` 选择工作区相对文件或整个目录；目录包含脏文件、被忽略文件与未跟踪的普通文件。`toolchain` 可以选择明确的绝对文件或目录。生成输出应放在动作的产物声明中，并排除在输入选择之外。Git 修订不能替代实际字节观察。

只有选择全部相关依赖后才能声明 `coverage: 'complete'`。owner 对选定字节、实际动作配置、Host 可执行文件／版本／环境与解析器设置生成指纹，并纳入 `ShellExecutor.verificationInputs` 报告的提供方可执行文件／配置输入。裸路径或不可用路径、不受支持的提供方枚举、链接、不稳定读取、缺失输入或观察上限都会使覆盖保持 unknown。本地 PowerShell 报告自身可执行文件和收集器配置。沙箱 PowerShell 提供方没有完整的只读隔离／运行时枚举，返回 null；独立的后续读取方也无法重建 agent（智能体）上下文，因此 agent 回执同样保持 unknown 覆盖／新鲜度，除非实际观察到的源码／配置变化确立 STALE。

每次树观察最多包含 4,096 个条目、每文件 128 MiB 和总计 512 MiB 字节。范围由显式审阅确定，不从命令字符串推测。执行前后的字节观察可以检测保留的变化；它们不会锁定项目输入，也无法检测两次观察之间修改后又恢复的瞬态编辑。

<a id="receipt-and-retention"></a>
## 回执与保留

[VerificationOwner](verification.ts) 在执行前发布意图，再在 Shell 启动前发布准备好的输入观察。由 ProjectActions 管理的 run ID 同时标识这两类记录与终态回执。配置修订通过实际观察到的配置／工作区摘要，独占发布并递增；还原配置不会复用早先修订。缺少运行前准备不能产生 PASSED，没有意图的旧运行仍只是历史执行事实。

`node-tap-13/1` 只解析完整且受支持的 Node TAP 日志。PASSED 要求非空的全部通过摘要、零退出，并且没有取消、超时、中断或截断。单独的零退出不能形成测试结论。不可变回执保留原测试事实；当前读取独立比较输入／配置并读取项目验收记录。STALE 不抹掉历史测试。验收使用独立的独占修订 CAS，只能通过认证的本地用户请求调用，模型工具不能调用。

声明产物的字节在本次运行结算时观察，并携带实际 run ID。两次运行具有相同字节时，仍然是两次独立观察。回执不认定文件写入者，也不声称产生了新文件。查询时的产物列表保持独立标签。

记录保存在 `desktop-actions/<workspace-digest>/verification/<run-id>`。回执保留自己的执行日志，最大为 1 MiB，与 ProjectActions 的 100 条终态运行／日志裁剪相互独立。保留回执身份按每页 100 个提供。回执／日志／配置／验收历史不会自动删除；现有原生配额计量这些文件，在容量不可用时拒绝进一步准入。目录发现最多读取 8,192 个条目，不会把截短扫描当作完整扫描。不受支持或损坏的记录拒绝读取，不替换原字节。

重开后缺少终态发布时返回 INTERRUPTED／UNKNOWN，不重放命令，也不从旧日志补造结果。日志丢失或摘要不匹配会使可读测试投影成为 UNKNOWN。完整文件的独占发布先同步文件字节，再让记录可见；真实断电、独立 SID 行为与恶意并发文件系统替换仍未获资格。

<a id="notification-delivery"></a>
## 通知交付

[NotificationOwner](notifications.ts) 消费已提交回执。来源 ID、结果修订与种类共同决定唯一持久 NoticeId。零退出的完成产生待验收通知；失败／未知执行与取消使用不同种类。官方 Session 终态使用独立来源 ID，由实际 Session ID、物理代次与 seq 派生。适配器使用官方 flush、observeDurable 与代次保护发布，将完整原始终态与实时事件匹配，拒绝不可用或合成观察。会话完成不是验证回执。错过回执回调后，协调过程读取保留结果；它不会重放命令或弹出历史通知。

偏好与共享系统消费游标使用持久修订 CAS。偏好默认为禁用，并跨 Host 重启保留。Main 在启动或重连时从当前已发布序号开始，因此不会弹出历史通知。新通知需要唯一的独占持久系统 claim。只有 OS show 事件到达后，Main 才记录 sent；明确拒绝记录 failed；未收到确认的尝试保留 unknown，不自动重试。禁用通知或推进启动基线会抑制弹出，不删除通知或回执。

系统交付、角色可见与显式用户处理分别记录。failed／unknown 交付仍保留可查的来源与通知。选择回执通知会打开回执；选择 Session 通知会打开当前恢复观察。只有用户主动定位成功后才将通知标记为已处理。处理通知不会验收验证结果。工作台更新同一持久偏好，没有第二个基于轮询的通知生产者。

<a id="companion-evidence-and-hint-choices"></a>
## 角色证据与 Hint 偏好

小鲸侧边分析使用独立的到期确认，不复用实验票据。它绑定真实空闲会话、工作区成员关系／路径、Host epoch、模型与连接修订、出口租约和已解析沙箱权限。权限、身份或客户端生命周期变化取消并排空这次官方请求。选定文字作为不可信输入，不带工具，也不写主会话历史。限制为输入 12 KiB、输出 1–2048 Token、零重试和 180 秒；配额或活动保留容量不可用时拒绝准入。精确来源标签、发送输入、结果和报告的 Token 用量位于 `nidofy-extras/experiments/side-analysis-v1`；金额保持未知。显式追加只授权原 scope 与当前权限下已经完成的结果。

按需历史每页展示当前会话与工作区的十条记录，并冷读其原始官方输入和结果。共享保留预算默认为二十条活动与八十条归档记录。独立的 120 秒预览及确认只归档已结束记录，在原目录独占发布 `archive.json` 并释放一个活动名额；不移动、替换或删除官方代次、输入、结果或日志。预算预览允许活动 1–20 条、归档 0–80 条，拒绝低于已保留数量的上限，在 `retention-v1` 下最多保留 256 个不可变预算修订。准入与保留共用原集合锁及原生 quota。确认重验完整所选记录、数量、预算、scope 和权限；过期、重复、变化及未结束操作均拒绝。读取和保留不准备提供方、不调用模型、不追加草稿或改变主历史。完整响应上限为 128 KiB；损坏或未来元数据原样保留并拒绝。物理断电及恶意文件系统替换仍未认证。

历史按全部、活动或已归档类别筛选后再分页，共享预算计数保持完整。所选记录导出使用独立的 120 秒预览与一次性确认，并校验当前 scope 和权限。在 `nidofy-extras/analysis-exports-v1` 下经原生配额独占发布一个 JSON，包含冷读日志及原始相对文件名和 base64 文件字节，包括原物理代次。每份导出上限为 512 KiB，最多保留 100 个文件；配额或容量拒绝不会删除既有导出。文件包含精确私人文本。记录变化、过期、重复确认和发布前取消均拒绝；已提交导出在随后断开连接时仍保留，不自动重试。导出只是本地证据副本，不导入、迁移、准备提供方、追加草稿或修改原记录。

可选伙伴口吻使用私有 `nidofy-extras/companion-style-v1.json`，带配额、原子 CAS 修订和有界操作回执。本地预览和显式执行绑定 scope 并到期；重复操作 ID 返回原回执。第一次官方 prompt 组装为当前回合捕获一次口吻选择，system message 通过正常循环记录。关闭后在已经捕获的活动回合结束时移除 prompt 注入。冷重开保留选择；未知或损坏数据拒绝且不替换字节。本地有限设置和桌宠协调展示由[客户端参考](../../../../packages/nidofy/desktop-extras/README.zh.md)负责。

`companion/facts` 读取官方原始耐久代次与前缀、已选定的 Notebook，以及最多 16 条保留的 T12 通知。Session 通知必须匹配原始代次、非继承 seq、回合、终态种类和时间；仅匹配逻辑 Session／cwd 时仍标为历史。回执来源使用真实 `VerificationOwner.inspect`，独立保留测试、新鲜度、日志可用性与验收。未知或不可读来源不能变成通过结果。Notebook 读取先取得自己的代次保护，再持有最终投影保护，避免嵌套取锁。提供方更换、取消或完整响应超过 1 MiB 时拒绝发布。读取不同步或重绑笔记、不创建通知、不推进游标、不 claim 投递、不处理通知，也不验收回执。

[Hint 偏好](hint-preferences.ts) 在 `desktop-actions/companion-hints/preferences` 下使用独立的 schema-version-1 不可变 CAS 修订，由现有动作配额覆盖。忽略、明确暂缓、准确 Workspace ID／路径静音，以及已展示返回卡身份均可冷读恢复。静音要求真实 Session 关联与可达目录；过期编辑、损坏或未来版本记录拒绝写入，不替换原字节。完整记录最多 1 MiB，目录发现最多 8,192 条，计入残留和发布空间。历史不会静默裁剪。写入结果不确定时重新读取，不自动重试。这些偏好不授予执行、投递或验收权限。[Client 参考](../../../../packages/nidofy/desktop-extras/README.zh.md)负责规则展示与导航。

<a id="known-limitations"></a>
## 已知限制

官方待批准事项仍由审批 owner 管理，此处尚未将其接为持久通知生产者。Desktop Companion owner 已发布显式 scope 与按需过滤视图。错过回执回调会协调补登记；错过 Session 回调时不会从全部历史 Session 日志冷重建。回执检查目前要求工作区目录可达；不可达时不删除保留文件。原始 Session 观察可能解码完整前缀，内存峰值仍未获资格。当前测试覆盖真实 Windows Node-mode Host／Shell／配额，以及使用已观察展示适配器的 Main 消费控制器；它们不资格化已安装 Electron 系统通知、renderer／preload 交互、企业网关、Office 转换、真实崩溃或安装包。

## 通知与恢复可见性

通知读取方接受 v1 与 v2，写入方为主会话原因和已观察的后台 job 终态写入 v2。过滤 awaited、teardown、内部工程和子代理活动。job 身份包含 runtime epoch；进程死亡前未观察的终态不能重建。原 v1 字节保留。仅接受 v1 的旧构建无法读取含新 v2 通知的 home。任务检查最多列出近期 100 个主会话，也接受准确的已保留 ID。打开会话仅执行只读导航，不自动恢复 agent。历史任务状态不提供取消权限。
