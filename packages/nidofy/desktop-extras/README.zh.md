# @nidofy/dsh-desktop-extras

[English](README.md) | 中文

## 概述

派生桌面版的「个人扩展」窗口管理本地诊断、合成缓存实验、独立识图连接和最多三个桌宠实例。这四项能力默认关闭，工作笔记和历史检索由 bundle 启用。模型执行、凭据、文件、会话、主题设置和计划任务仍由官方服务负责。配套 bundle 通过官方 profile Loader 装载本插件。

## 使用本包

实际 Notebook 贡献变化先撤回旧能力观察，再触发一次有界认证读取。Notebook Client 卸载后角色 owner 继续存活；此生命周期订阅不增加周期轮询。

构建、产物与宠物显示／静音使用原工作台入口；仓库写入仍先预览、再确认。审批动作只定位官方待处理审批。近期事实展示[重验后的物理来源与回执检查](../../../apps/desktop-host/src/workbench/README.zh.md#companion-evidence-and-hint-choices)，分别标注测试、时效与验收。会话结束和 Notebook 文案不能确立测试 PASSED。共享弹窗保留组合事件保护和焦点；图形释放遵循单角色注册生命周期。

Hint 使用当前交互、已提交活动笔记、过期回执、相同命令的重复保留失败日志，以及已准入的已安装导航。人工修正替换较早笔记修订；忽略旧来源修订不能隐藏后续修正。忽略、暂缓 15 分钟、准确项目静音／恢复与显式重置只影响 Hint 展示。暂缓到期在下次读取或导航时检查。导航后的返回卡提供尚未展示的 Hint 身份；可见卡片的展示确认独立于通知，持久记录去重。scope／权限／来源变化撤回旧提示，取消拒绝迟到读取；偏好不可读时不会启用默认提示。未安装的 Notebook UI 不提供入口。规则不调用模型、不发送消息、不执行任务，也不安装插件。

Desktop Client 的 `ctx.companion` 独立于桌宠和 Notebook 开关。scope 来自认证的真实 Host epoch、Main 窗口 ID、显式导航 SessionBinding、实际 Conversation target／panel、Workspace 成员关系及 turn；缺身份使用 null。切换、重连、权限与待处理请求变化取消旧操作并拒绝迟到结果。默认不增加模型请求。显式关注只保留一个真实旧会话引用，不持久化重启意图；新 scope 不重绑或删除旧 Notebook 代次。

角色通过 shell.accessory 使用 300px 宽栏；中心扣除官方侧栏后小于 1040px 时提供同一 owner 的可访问小鲸弹窗。关闭弹窗保留主会话草稿与附件。环境位于顶部，状态与操作居中，角色画面位于底部。折叠项的展开标记与文字统一对齐，展开设置使用独立的带标签输入行。静态回退使用蓝鲸透明上半身和头像。显式选择本地 Live2D 只加载固定模型与包内 Cubism Web 5-r.5 Core／Framework；Idle 动作没有会话或模型权限。隐藏时停止，资源或 WebGL 失败保留静态立绘，卸载释放图形资源。来源美术资产保留在本地，版本库仅收录运行模型与静态回退资源。SDK 准备脚本要求本地已取得的 SDK，并保留使用条件；生成的 SDK 产物不进入版本库。美术接缝和 GPU 显存峰值仍未认证。单一 nidofy.companion 插槽接收 active、完整 view 与 act。环境默认折叠，只在显式展开或刷新时读取，不做周期 context/status 轮询。主题与字体继续使用官方设置。

侧边分析只对空闲的前台会话开放。选择受管连接和模型，输入选定文字，核对精确请求后确认一次请求。结果、用量和独立官方请求记录留在侧栏。历史按需加载本会话记录，提供原始记录、显式归档预览及共享保留预算预览；确认保留原请求、结果与日志，历史和保留操作不发送或追加。显式追加当次已完成结果会重验当前 scope 与 composer 修订，保留文字、引用、附件和选择，形成一个撤销步骤而不发送。关闭、切换会话或权限变化取消待处理工作。权限、预算与保留规则由 [Host 参考](../../../apps/desktop-host/src/workbench/README.zh.md#companion-evidence-and-hint-choices)负责。

分析历史可筛选全部、活动和已归档记录，切换筛选会重置分页。“预览本地记录导出”明确选择一条显示记录，确认后将完整原始请求、结果和本地文件精确字节保存到展示的本地路径，包含私人文本。放弃预览不会写入文件；回执显示保存路径。筛选和导出不追加草稿或发送模型请求，scope 变化会撤销待完成操作。

自然语言设置列出已有十二项本地动作，选择仅填入指令，不会预览或执行。界面显示当前 Session、Workspace 和所选桌宠，不使用桌宠的动作明确说明。预览和明确确认将关注、已安装入口、所选已配置桌宠或可选会话口吻委托给原所有者，并显示实际回执。停止关注的预览标明实际关注的 Session，目标变化时拒绝执行。显示的本地截止时间沿用原所有者较早期限，最多六十秒；过期后禁用确认，新预览须明确选择。未知短语、任意配置、路径和 Shell 指令拒绝，不调用模型。口吻默认关闭，从主会话下一回合生效并记录到官方 system message；代码、命令与正式交付保持精确普通语言。动画不提供口吻或权限。预览或执行期间可取消等待，迟到结果不会展示；取消无法撤销原所有者已经提交的操作。指令、scope 或所选桌宠变化会清除待完成控件。“读取当前设置”明确读取当前作用域下原口吻、所选桌宠和关注 owner，不预览或执行。带读取时间的数值是快照，不是操作回执。重新读取、取消、目标变化及失败均撤下旧值，新预览仍需单独选择。

角色的桌宠关注控件显式选择一个已配置桌宠实例，可绑定／解除前台会话、静音／启用气泡或本地招手。上次读取的设置显示实例启用、Session 绑定与气泡静音状态。明确刷新会在读取期间撤下旧选择，读取失败时操作保持不可用。等待桌宠动作时禁用目标选择与刷新，回执保留所选目标和原 owner 的实际结果。绑定是 Session 级，独立于之后的前台切换，不授予动作／run 权限或模型请求。Main 只接纳当前 app 顶层 frame 和完整 Companion 作用域。命令含唯一动作身份、目标、偏好修订、feed 代次与过期时间；重复、旧作用域、已关闭桌宠及过期命令拒绝且不重试。较旧的固定 Session 按需从官方读取 owner 补载，不补播反应。桌宠导航只送到 Main 选择的主窗口。关闭 pets 后角色、Notebook 和通知 owner 继续可用。

启用 T12 系统通知时，桌宠终态气泡让位于系统通知；通知偏好未知时先抑制重复终态气泡，直到可读。这不确认、处理或认证任何通知的发送。静音模式隐藏桌宠气泡。当前状态说明及独立角色事实继续显示。本地互动只更新既有可选亲密度偏好和表现，任务状态与执行仍归原 owner。

环境卡片就地展开变更、文本差异、本地仓库信息和分支操作。操作菜单提供提交、推送、创建分支与切换分支；写操作先预览、再明确确认，并遵循部署保护策略。提交仅包含已暂存文件。详情提供独立的完整工作台入口；连接设置通过明确的编辑器入口打开。切换会话会重置详情与待确认预览。

在 Nidofy 桌面发行版打开「应用 → 个人扩展」，按需启用并保存。插件管理器可停用整个插件；连接、文件保护和工程工作台由独立模块负责。原生恢复会移除其 bundle，后续启动保留这一选择。

本地自检打开[正式 Desktop 自检](../../../apps/desktop-host/src/selftest/README.zh.md)。隔离本机模式不请求模型，连接模式要求确认固定模型、修订和预算。两者保留逐项报告与中断冷读，只导出允许字段。打开页面不执行检查。原服务存在入口改为拒绝，不再发布 PASS；见[升级指南](../../../docs/upgrade-guide/v0.2.0-rc.2/electron-selftest/guide.zh.md)。

缓存实验需要选择禁用重试且上下文上限已知的连接，输入预算为 512、2048 或 8192 个估算 token，请求数为四次或六次。确认后仅发送合成文本。字符数除以四只是估算；字节与服务端报告的 token 分别记录。缺少缓存计数或延迟变短不能证明命中。旧字节预算必须重新选择，不会自动执行。

识图需要在受管理连接或官方连接上选择支持图片的模型。本地操作确认发送一张图片和问题；可选的 `analyze_image` 工具让 Agent 请求同一操作。请求使用官方 prepared-call 链路，图片使用官方附件存储。关闭识图会取消并等待在途请求结束，同时移除工具。

桌宠资源支持本地预检、摘要校验导入、明确替换、ZIP 导出与删除。内置资源只读。各实例独立设置大小、固定会话、位置、互动、观察方向、安静模式、本地心情和气泡。资源索引损坏时保留原文件，并保持内置资源回退可用。

桌宠菜单在宠物旁展开，按 Escape 或失去焦点时关闭。「自动关注任务」立即解除固定会话，依次优先选择等待处理、阻塞、运行中的任务，最后显示短暂的完成提示；没有活动任务时进入闲置状态。菜单显示关注模式和会话短标识，双击宠物可打开所关注会话。

在官方插件管理器启用「自动化任务」，即可使用预置 schedule 服务，无需下载包。导入经审阅的 `schemaVersion: 1` JSON 清单，其 `items` 数组包含标题、提示词及可选时间元数据。导入项目保持暂停；逐项选择已有主会话、新的未来规则及默认不勾选的独立确认后恢复。间隔初始为空；旧时间元数据不替用户选择规则。恢复中断后保留结果未知状态，不能自动重试。

工作笔记和历史位于环境卡片内。默认检索当前会话，exact cwd 与用户关联项目均需明确选择。本地三元组补充官方短语召回和有界短查询窗口。候选保留物理代次和原事件定位；预览及显式插入草稿都重验真实来源和项目权限。既有 `@` 选择器保持只读引用行为。检索错误与空结果彼此独立。关联持久化、索引重建、预算和限制由[工作笔记参考](../working-notebook/README.zh.md)说明。

工作笔记由独立的[工作笔记插件](../working-notebook/README.zh.md)启用，该插件负责笔记工具、提示词快照及可选压缩增强。本包的共享库导出不会自行启用这些功能。

工作笔记产品使用 `installContextV2`。启动和成功压缩会补齐官方原始耐久前缀并保留物理 scope；工具与回合快照只读取选定指针，不触发恢复写入。发布在 storage admission 期间持有代次保护，在选择 current 指针前再次核对设置和 provider 生命周期。之后的诊断失败不会撤销成功。数字代次的旧 v2 数据和改变的 scope 会明确拒绝，不改动已提交文件；参见[升级指南](../../../docs/upgrade-guide/v0.2.0-rc.2/notebook-v2-generation/guide.zh.md)。旧 v1 库入口保留，桌面产品使用 v2。Notebook 替换是原子的；既有工具不承诺断电耐久性。Session 回执不充当 Notebook 提交点。

<a id="ownership-and-persistence"></a>
## 所有权与持久化

产品的 `./storage` 插件要求应用拥有的 Windows helper 绝对路径。校验后的 `limitBytes` 与 `safetyBytes` 初始化发行根账本；已有账本设置跨重启保留。受管写入在多个 Host 间共享原生同步确认的授予，并保留独立终态容量。[配额格式参考](../../../native/nidofy-protection/README.zh.md)定义物理根归属、恢复与排除项。它不增强 Notebook 文件耐久性。只读 inventory 不能授权写入。

连接设置提供认证后的「存储与配额」页面。状态区分缓存计量、核算字节与预留；恢复需明确确认。快照导入要求校验，工程恢复另行选择。清理仅提供候选项。旧版导入通过[原生配额 owner](../../../native/nidofy-protection/README.zh.md)提供类别／配置预览、有界执行、已提交报告复核、操作查询／恢复及独立原位接纳。显式选择 home 只准备后续启动参数；ready/adopted 不切换当前 Host。接纳保留导入排除项费用。工作区命令信任、保护路径及暂停计划各有独立确认 owner；参见[迁移指南](../../../docs/upgrade-guide/v0.2.0-rc.2/nidofy-quota/guide.zh.md)。

偏好、实验回执、报告归档、桌宠资源和隔离的计划清单位于 `$DSH_HOME/nidofy-extras`。偏好使用修订检查和原子替换。无法读取偏好时关闭可选功能并保留源文件。诊断归档排除提示词、回答、凭据和文件正文；用户可控的连接与模型名称转换为进程内 HMAC 标识。归档上限为 100 个文件和 50 MiB。观察器失败不能替换模型流片段或已提交会话事件。

工作笔记在本包内带有版本化存储。v1 存储把退休条目保留在同一个有界快照内；v2 `NotebookV2Store` 将活动集与只追加的历史日志分离并单独限制磁盘预算，按会话代次记录证据与提交双游标，且退休 ID 永不复用。发布时先追加日志记录，再经由先写完整的临时文件发布一个内容派生命名的不可变修订，使写失败不会在最终路径留下半文件，最后原子替换 `current.json`；指针中记录的已提交日志长度用于隔离崩溃残留，下一次发布重新观察真实日志、追加前截断未提交尾部，并复用字节相同的修订文件。内容派生同名且字节不同的既存文件一律以具名诊断拒绝改动并保留原字节，因为它是否曾提交无法由文件内容、文件名或修订号判定。v2 转换把 v1 笔记复制到独立命名空间并保持原字节不变，指针写失败后的重试不重写字节相同的历史日志、不复制修订文件，未知旧格式以可修复诊断拒绝而不被覆盖。publish 的 signal 同样会在其惰性转换的首个磁盘写之前中止；仅由读取触发的转换则运行到完成。任何预算超限都以具名错误失败，不会静默丢弃置顶或退休证据。

公共 `./notebook` 导出提供 `NotebookV2Store.readCommitted(scope, signal)`，返回包含双游标及活动条目的独立选定状态；这一恢复读取会验证已提交历史，也可能转换 v1。`readSelected(scope, signal)` 只读取当前 v2 指针，排除内部字节记账，以 `NOTEBOOK_RECOVERY_REQUIRED` 拒绝仅有旧格式的状态，不写转换文件；历史验证由显式恢复、历史读取及发布负责。产品的 `nidofyNotebookV2.read` 在真实代次保护下使用轻量读取，`synchronize` 显式补齐耐久候选，`synchronization` 提供进程内整理状态。`readActive` 保持为有界活动投影。

v2 压缩安装器保留官方 Basic 引擎，要求请求事件已登记。活动输入、完整证据附录和带原始标签的 delta 使用独立 UTF-8 预算。按顺序选择完整事件；超大事件停止证据推进。Required 的 `nidofy/notebook-compaction` 记录保留准确请求，供候选重建。发布要求匹配的成功持久标记、设置生命周期及笔记修订。旧 v1 增强器把 provider 失败交回官方引擎处理，不再隐式发送第二次请求。

原生适配器仅负责透明窗口及发送方校验 IPC。桌宠导航使用官方工作区服务。主题和字体使用官方客户端设置。计划存储和投递使用官方 schedule 服务。本包不创建 Agent Loop 或 Session writer。不提供 invariant companion：偏好只有一个串行写入所有者，状态与桌宠视图是由消费者验证的可销毁投影。

<a id="model-experience"></a>
## 客户端生命周期与本地控制

伴随栏按 Host epoch 与会话保留未发送草稿，撤销陈旧动作结果，并在主面板打开时保留导航。读取当前设置必须显式触发，不会重放已取消动作。设置中的通知偏好保持显式启用；失败后必须重新读取 owner 修订。模型设置另列托管连接的归属。管理文档共享本地化主题与确认控件，同时保留认证 Host 路由。诊断缓存率要求输入、缓存读取和缓存写入三桶覆盖；SDK 计数不能证明提供方明确报告了零。终止步骤中未结算的工具标为未确认，不虚构结果或时长。


## 模型体验

### 可选图片工具与明确请求

#### 模型可见内容

仅启用识图时添加 `analyze_image`。所选服务端看到图片和问题，不包含会话历史。诊断和桌宠不添加模型可见内容。缓存实验发送独立、经用户确认的合成请求。恢复后的计划遵循官方 schedule bundle 的工具与消息约定。

侧边分析只通过所选连接发送已记录的来源标签和选定文字，不带工具，也不自动插入主聊天。可选伙伴口吻在后继主回合中添加已日志化的 system 段，改变该 prompt 前缀；它不产生独立模型请求，也不承诺缓存收益。本地有限设置和 Live2D 不发送模型输入。

#### Token 影响

启用图片工具时添加其 schema，并把分析文本返回调用 Agent。主动实验每次最多请求 64 个输出 token。诊断、桌宠和外观设置不消耗模型 token。

#### KV Cache 影响

启用识图会改变工具 schema 前缀。原生缓存模式保持请求不变；关闭模式移除路由键；会话模式针对允许的 OpenAI 兼容模型，用准备好的服务端、模型、地址、数据目录和会话生成 HMAC 键。`/cache` 库的 `prepareDesktopCachePayload` 捕获已验证偏好，由产品 hook 和隔离自检共用。`desktopCacheObservation` 从该实际 callback 返回独立的已应用提示、捕获的策略及可用的偏好修订；不同 bundle 共享 callback 自带的观察身份，不保留缓存键。修改使用请求副本，路由键以外的所有字段保持。稳定的键不证明前缀稳定或缓存命中。插件重载会更换 HMAC 密钥，因此缓存键和诊断指纹不跨重载保持。只读 `ctx.nidofyCacheInput` 服务捕获实际偏好修订、启用／挂载状态和独立完整策略，不准备 payload，也不暴露密钥／凭据；重载撤销其 owner 身份。已确认工程试验重验该来源，并另外观察实际应用的提示。当前策略不填补历史观察，见[服务契约](../../../docs/subsystems/llm-streaming.zh.md#desktop-cache-input)。

## 已知限制与待办

<a id="known-limitations-and-deferred-work"></a>

- 合成服务验收证明协议与路由行为，不证明厂商实际计费缓存收益或识图质量。真实凭据与企业网关验收需要对应环境。
- 计划清单是明确导入，不会自动解释旧调度器数据库。恢复结果未知时应检查官方任务目录。
- 原生桌宠适配器面向 Windows Desktop。本插件随派生发行版分发，尚未发布 npm。未来独立分发必须分别验证包兼容性及各平台原生适配。
- 独立 CLI profile 使用官方 CLI 的执行行为。桌面连接和保护适配器由 Desktop Host 装载，不承诺任意 CLI profile 具备相同能力。
- Notebook 启动、耐久观察和冷 JSONL 解码仍扫描完整日志。元数据缓存不保存原始历史；原始事件和搜索直接使用查询所有者。热态 committed 读取避免耐久扫描，最近来源响应读取配置限定的窗口。缓存淘汰后，取得实际代次可能需要再次全量观察。
- 1k/10k/100k 合成历史测量热态路径改善，不代表长任务质量或真实部署资格。当前没有按范围取得耐久观察的公共 API；取得完整原始前缀后，恢复仅扫描实际提交游标后的候选后缀。
