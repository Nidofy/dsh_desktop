# @nidofy/dsh-desktop-extras

English | [中文](README.zh.md)

## Summary

The derived Desktop's Personal extensions window controls local diagnostics, synthetic cache experiments, an independent image connection and up to three desktop pets. These four capabilities start disabled; working notes and history are enabled by the bundle. Official services retain model execution, credentials, files, Sessions, theme settings and scheduling. The companion bundle installs this plugin through the official profile Loader.

## Use this package

Actual Notebook contribution changes withdraw the old capability observation and trigger one bounded authenticated reread. The companion owner survives Notebook Client unloading; this lifecycle subscription adds no periodic polling.

Builds, artifacts and pet display/quiet settings use existing workbench navigation; repository writes still require preview and confirmation. Approval navigation only locates an official pending approval. Recent progress shows [revalidated physical sources and receipt inspections](../../../apps/desktop-host/src/workbench/README.md#companion-evidence-and-hint-choices), with separate test, freshness and acceptance labels. Session completion and Notebook prose never establish test PASSED. The shared modal preserves composition guards and focus; graphics disposal follows the single character registration.

Hints use current interactions, committed active notes, stale receipts, repeated retained failed logs for the same command, and admitted installed navigation. User corrections replace earlier note revisions; ignored source revisions cannot hide a later correction. Ignore, 15-minute snooze, exact-project mute/unmute and an explicit reset affect Hint viewing only. Snooze expiry is checked on the next read or navigation. A return card offers unseen Hint identities after navigation; opening its complete progress content confirms offered hints separately from notifications; a collapsed summary does not acknowledge the group. Scope/permission/source changes withdraw old hints, cancellation refuses late reads, and an unavailable preference read never enables default hints. Uninstalled Notebook UI is not offered. No rule calls a model, sends a message, executes a task or installs a plugin.

Desktop Client `ctx.companion` stays independent of pets and Notebook switches. Its scope combines the authenticated actual Host epoch, Main window ID, explicit navigation SessionBinding, actual Conversation target/panel, Workspace membership and turn; missing identities remain null. Navigation, reconnect, permission and pending-request changes cancel old operations and refuse late results. It makes no additional model requests by default. Explicit attention retains one real prior Session reference without persisting restart intent; a new scope never rebinds or deletes an old Notebook generation.

The companion uses local Assistant, Project and Tools modes above one project summary, status strip and persistent character stage. Assistant offers Working notes and Recent progress, with compact conversation and pet attention controls. Project opens the shared environment details, builds, files and snapshot protection; Tools opens model connections, side analysis and finite quick settings. The more menu provides character display, pet settings, status details and a layout-only reset. Mode changes do not send messages, change the model or alter the main draft. One secondary view scrolls beneath the compact stage; closing it restores the chosen framing. A 300px rail becomes the existing controlled modal below the 1040px center threshold. Theme and fonts retain their official settings.

Character animation remains opt-in and uses the fixed offline Cubism Web 5-r.5 adapter and Idle motion. Full, half-body and portrait framing update backing dimensions, viewport and projection in one renderer without reloading resources; DPR is capped at two within four megapixels. The static upper-body resource supports half-body and portrait only. Replacement character slots may ignore optional presentation preferences; their unavailable framing controls stay disabled. Hidden views stop rendering, and graphics failure retains the static fallback until explicit retry. Animation controls and errors live in Character display rather than over the portrait. Source artwork stays local; runtime model and static fallback assets remain versioned. The SDK preparation script requires the locally acquired SDK and retains its notices; generated SDK outputs are not versioned. Art seams and GPU memory peaks remain unqualified.

Side analysis opens only for the idle foreground Session. Select a managed connection and model, enter selected text, review the exact request and confirm one request. Results, usage and an independent official request journal stay in the side surface. History loads on demand for this conversation and offers original records, explicit archive previews and shared retention budget previews. Confirmation keeps the original request, result and logs; history and retention never send or append. Explicit append of a fresh completed result rechecks the current scope and composer revision, preserves text, references, attachments and selection, and creates one undo step without sending. Closing or changing modes while an operation is pending first offers continued viewing or cancellation of waiting; this does not guarantee zero usage or undo an owner commit. Session or permission changes still cancel pending work. The [Host reference](../../../apps/desktop-host/src/workbench/README.md#companion-evidence-and-hint-choices) owns authority, budgets and retention.

Analysis history offers all, active and archived filters and resets pagination when the filter changes. Preview local record export selects exactly one displayed record; confirmation saves its full original request, result and exact local file bytes to the displayed local path. Private text is included. Dismissing the preview writes nothing. The receipt displays the saved path; filtering and export never append to the draft or send a model request. Scope changes withdraw pending operations.

Natural settings list all twelve existing local actions. Selecting one fills the instruction without previewing or executing it. The surface shows the foreground Session, Workspace and selected pet; actions that do not use a pet say so. Preview and explicit confirmation delegate attention, installed navigation, the selected configured pet or optional Session tone to their existing owners and show actual receipts. Stop-following previews identify the actual followed Session and refuse a changed target. The displayed local deadline keeps the earlier owner expiry, at most sixty seconds; expired confirmation is disabled and a new preview is explicit. Unknown phrases, arbitrary configuration, paths and Shell instructions refuse without a model request. Tone is disabled by default, takes effect at the next main turn and is recorded in the official system message; code, commands and formal deliverables retain precise ordinary language. Animation never supplies tone or permissions. Waiting can be cancelled during preview or execution. Late results are withdrawn; cancellation cannot undo an action already committed by the owner. Changing the instruction, scope or selected pet clears pending controls. Read current settings explicitly reads the existing tone, selected pet and attention owners for the current scope, without previewing or executing. Its timestamped values are a snapshot, not an action receipt. Refresh, cancellation, target changes and failures withdraw old values; a new preview remains a separate choice.

The companion's Desktop pet attention controls explicitly select one configured pet instance and bind or release the foreground conversation, mute/unmute its bubbles, or wave locally. The last read settings show instance enablement, Session binding and bubble quiet state. Explicit refresh withdraws stale choices while reading; failed reads keep actions unavailable. Waiting for a pet action disables target selection and refresh, and receipts retain the selected target with the actual owner result. Binding is Session-level, independent of later foreground changes; it grants no action/run permission or model request. Main admits only the current app top frame and complete Companion scope. Commands carry a unique action identity, target, preference revision, feed generation and expiry; duplicates, stale scopes, disabled pets and expired commands refuse without retry. Older pinned Sessions load from the official read owner on demand without replaying reactions. Pet navigation goes only to Main's chosen main window. Closing pets leaves the character, Notebook and notification owners available.

Pet terminal bubbles defer to enabled T12 system notifications; an unknown notification preference suppresses duplicate terminal bubbles until readable. This does not acknowledge, handle or certify delivery of any notice. Quiet mode hides pet bubbles. Current state captions and independent Companion facts remain visible. Local interactions update only the existing optional affinity preference and presentation; task state and execution stay with their original owners.

The project summary and Project environment action open the same details, with changes, text diffs, local repository information and branch actions inline. Its action menu offers commit, push, create branch and switch branch; mutations require a preview followed by explicit confirmation and inherit deployment protection. Commit includes staged files only. Details expose a separate full-workbench link. Connection settings open through an explicit editor link. Changing conversations resets details and pending previews.

Open Application → Personal extensions in the Nidofy desktop distribution. Enable the capabilities you need and save. The plugin manager can disable the entire plugin; connections, protection and the engineering workbench have separate owners. Native recovery removes its bundle and subsequent launches preserve that choice.

Local checks opens the [formal Desktop self-test](../../../apps/desktop-host/src/selftest/README.md). Its isolated local mode makes no model requests; connection mode requires a fixed-model, revision and budget confirmation. Both retain per-check reports and cold interrupted state, and export only allowed fields. Opening the page does not run checks. The former presence endpoint refuses instead of publishing PASS; see the [upgrade guide](../../../docs/upgrade-guide/v0.2.0-rc.2/electron-selftest/guide.md).

Cache experiments require a selected connection with retries disabled, a known context limit, a budget of 512, 2048 or 8192 estimated input tokens and four or six requests. Confirmation sends synthetic text only. Character count divided by four is an estimate; bytes and reported token counters remain separate. Missing cache counters or shorter latency do not prove a cache hit. Legacy byte budgets require a new explicit choice and never run automatically.

Vision requires an image-capable model on a selected managed or official connection. The local action confirms one image and question; the optional `analyze_image` tool lets an Agent request the same operation. Provider requests use the official prepared-call path. Image attachments use official storage. Disabling vision cancels and drains its requests and removes the tool.

Pet resources support local preview, digest-checked import, explicit replacement, ZIP export and deletion. Built-in resources are read-only. Each instance has independent size, pin, position, interactions, gaze, quiet mode, local mood and bubble settings. Corrupt resource catalogs preserve the file and retain the built-in fallback.

The pet menu opens beside the sprite and closes on Escape or loss of focus. Auto-focus tasks immediately releases a pinned Session and prioritizes waiting tasks, blocked tasks, running tasks, then recent completion notices. With no active task the pet idles. The menu shows the selection mode and a short Session identifier; double-clicking the pet opens that Session.

Enable Automation tasks in the official plugin manager to use the bundled schedule service without downloading packages. Import a reviewed `schemaVersion: 1` JSON manifest with an `items` array of title, prompt and optional timing metadata. Imported rows remain paused. Restore each to an existing root Session with a new future rule and a separate unchecked confirmation. The interval starts blank; old timing metadata never selects a rule. An interrupted restore stays unknown and cannot be retried automatically.

Working notes and history open through Assistant → Working notes in the existing Notebook slot and a controlled modal. Search defaults to the current Session; exact cwd and user-associated projects are explicit choices. Local trigrams supplement official phrase recall and the bounded short-query window. Every candidate retains its physical generation and original-event locator; preview and explicit draft insertion recheck actual source and project permission. The existing `@` picker keeps its read-only reference behavior. Search errors remain distinct from no matches. The [working-notebook reference](../working-notebook/README.md) owns association persistence, index reconstruction, budgets and limitations.

Working notes are activated separately by the [working-notebook plugin](../working-notebook/README.md), which owns note tools, prompt snapshots and the optional compaction enhancement. Shared library exports here do not activate those features.

The working-notebook product uses `installContextV2`. Startup and successful compaction reconcile the official raw durable prefix and retain its physical scope. Tools and turn snapshots read the selected pointer without recovery writes. Publication holds generation protection through storage admission and rechecks settings and provider lifetime before selecting the current pointer. Later diagnostic failure does not reverse success. Numeric legacy v2 generations and changed scopes refuse without altering committed files; see the [upgrade guide](../../../docs/upgrade-guide/v0.2.0-rc.2/notebook-v2-generation/guide.md). Legacy v1 library entry points remain available, but the desktop product uses v2. Notebook replacement is atomic; the existing file utility does not promise power-loss durability. A Session receipt is not the Notebook commit point.

## Ownership and persistence

The product's `./storage` plugin requires an absolute application-owned Windows helper path. Its validated `limitBytes` and `safetyBytes` initialize the distribution ledger; existing ledger settings survive restarts. Managed writes share native sync-confirmed grants across Hosts, with separate terminal capacity. The [quota format reference](../../../native/nidofy-protection/README.md) defines physical root ownership, recovery and exclusions. It does not strengthen Notebook file durability. The read-only inventory cannot authorize a write.

Connection settings link to the authenticated Storage and quota page. Status separates cached measurement, reconciled bytes and reservations; recovery requires explicit confirmation. Snapshot imports require verification and project restoration needs separate selection. Cleanup offers candidates only. Legacy intake offers category/configuration preview, bounded execution, committed-report review, operation inspection/recovery and separate in-place adoption through the [native quota owner](../../../native/nidofy-protection/README.md). An explicit home choice prepares later launch parameters; ready/adopted never switches the running Host. Adoption retains excluded import charges. Workspace command trust, protection paths and paused plans have independent confirmation owners; see the [migration guide](../../../docs/upgrade-guide/v0.2.0-rc.2/nidofy-quota/guide.md).

Preferences, probe receipts, report archives, pet resources and quarantined schedules live under `$DSH_HOME/nidofy-extras`. Preferences use revision checks and atomic replacement. Unreadable preferences disable optional capabilities and preserve the source. Diagnostic archives omit prompts, answers, credentials and file contents; user-controlled provider and model labels become process-local HMAC identifiers. Archives are bounded to 100 files and 50 MiB. Observer failures cannot replace model chunks or committed Session events.

Working notes carry a versioned store in this package. The v1 store keeps retired entries inside one bounded snapshot; the v2 `NotebookV2Store` separates the active set from an append-only history journal with its own disk budget, records dual evidence and commit cursors per Session generation, and never reuses a retired id. A publish appends journal records, publishes one content-derived immutable revision file through a completed temporary so a failed write never leaves a partial final file, then atomically replaces `current.json`; the committed journal length recorded in that pointer fences crash residue, and the next publish re-observes the real journal, truncates an uncommitted tail before appending, and reuses an identical revision file. A pre-existing file holding different bytes at the same content-derived name is refused untouched with a named diagnostic, because whether it was ever committed cannot be determined from the file, its name or its revision number. The v2 conversion copies a v1 notebook into a separate namespace and leaves the original bytes untouched, retries a failed commit pointer without rewriting identical journal bytes or duplicating the revision file, and refuses unknown legacy formats with a repairable diagnostic instead of overwriting them. A publish signal also aborts its lazy conversion before the first disk write; plain reads that trigger the conversion run it to completion. Writes above any budget fail with a named error rather than dropping pinned or retired evidence silently.

The public `./notebook` export provides `NotebookV2Store.readCommitted(scope, signal)`, a detached selected state including both cursors and active entries; this recovery reader validates committed history and may convert v1. `readSelected(scope, signal)` reads only the current v2 pointer, excludes internal byte accounting, and refuses legacy-only state with `NOTEBOOK_RECOVERY_REQUIRED`. It makes no conversion writes and leaves history validation to explicit recovery, history reads and publication. Product `nidofyNotebookV2.read` uses this lightweight reader under actual generation protection. `synchronize` explicitly reconciles durable candidates, and `synchronization` exposes process-local progress. `readActive` remains the bounded active projection.

The v2 compaction installer retains the official Basic engine and requires the registered request event. Active input, complete evidence appendix and raw tagged delta use separate UTF-8 budgets. Whole events are selected in order; an oversized event stops evidence advancement. Required `nidofy/notebook-compaction` records retain exact requests for candidate reconstruction. Publication requires matching successful durable markers, settings lifetime and notebook revision. The legacy v1 enhancer propagates provider failures to the official engine instead of making an implicit second request.

The native adapter owns only transparent windows and sender-checked IPC. Pet navigation uses the official workspace service. Theme and font settings use the official client. Schedule storage and delivery use the official schedule service. This package creates no Agent Loop or Session writer. No invariant companion is published: preferences have one serialized owner, while status and pet views are disposable projections verified at their consumers.

## Client lifecycle and local controls

The Companion retains unsent drafts per Host epoch and Session, withdraws stale action results, and keeps navigation available while a main panel is open. Current-setting reads are explicit and never replay a cancelled action. Notification preferences are opt-in controls in Settings; failures require rereading the owner revision. Models settings lists managed connection ownership separately. Management documents share localized theme and confirmation controls while retaining authenticated Host routes. Diagnostic cache rates require coverage of input, cache-read and cache-write buckets; SDK counts do not establish that a provider explicitly reported zero. Unsettled tools at a terminal step are shown as unconfirmed without an invented result or duration.


## Model Experience

### Optional image tool and explicit requests

#### What the model sees

Vision adds `analyze_image` only while enabled. Its selected provider sees the image and question, without the conversation history. Diagnostics and pets add no model-visible content. Cache experiments make separate user-confirmed synthetic requests. Restored schedules follow the official schedule bundle's tool and message contracts. Side analysis sends only its logged source labels and selected text through the chosen connection, with no tools or automatic main-chat insertion. Optional companion tone adds a logged system section to subsequent main turns, changing that prompt prefix; it makes no separate model request and promises no cache benefit. Local finite settings and Live2D send no model input.

#### Token effect

The image tool adds its schema while enabled and returns analysis text to the calling Agent. Explicit probes request at most 64 output tokens per request. Diagnostics, pets and appearance settings consume no model tokens.

#### KV Cache effect

Enabling vision changes the tool-schema prefix. Native cache mode leaves provider payloads unchanged; off mode removes the routing key; session mode supplies an HMAC scoped to the prepared provider, model, endpoint, home and Session for allowlisted OpenAI-compatible models. The `/cache` library's `prepareDesktopCachePayload` captures the validated preference and is shared by the product hook and isolated self-tests. `desktopCacheObservation` reads the detached applied hint, captured policy and available preference revision from that actual callback; separate bundles share its callback-carried observation identity without retaining the cache key. Payloads are copied; every field except the routing hint stays unchanged. A stable hint does not prove a stable prefix or cache hit. The HMAC secret changes on plugin reload, so keys and diagnostic fingerprints do not persist across reloads. The read-only `ctx.nidofyCacheInput` service captures actual preference revision, enabled/mounted state and a detached complete policy without preparing a payload or exposing keys/credentials; reload revokes its owner identity. Confirmed engineering trials revalidate this source and separately observe the actual applied hint. Present policy never fills historical observations; see the [service contract](../../../docs/subsystems/llm-streaming.md#desktop-cache-input).

## Known Limitations and Deferred Work

<a id="known-limitations-and-deferred-work"></a>

- Synthetic provider qualification proves protocol and routing behavior, not a vendor's billed cache benefit or image quality. User credentials and enterprise gateway acceptance need their own environment.
- Schedule manifests are explicit imports, not an automatic reinterpretation of old scheduler databases. Unknown restore outcomes require inspection in the official task catalog.
- The native pet adapter targets Windows Desktop. This plugin is private and shipped with the derived distribution; it is not published to npm. Future extraction must qualify package compatibility and native adapters on each platform.
- Independent CLI profiles use the official CLI's execution behavior. Desktop connection/protection adapters are installed by Desktop Host and are not promised for arbitrary CLI profiles.
- Notebook startup, durable observation and cold JSONL decoding still scan the full log. The metadata cache stores no raw history; session/event source and search routes use their query owner directly. Warm committed reads avoid durable scans, while recent-source responses read a configured bounded window. Cache eviction can require a new full observation to acquire the actual generation.
- Synthetic 1k/10k/100k histories measure warm-path improvements, not long-task quality or real deployment qualification. No range-based durable observation exists yet; recovery scans only the candidate suffix after the actual commit cursor once the full raw prefix has been obtained.
