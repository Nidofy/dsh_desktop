# Nidofy quota journal

English | [中文](README.zh.md)

## Ownership

The Desktop Host [storage service](../../packages/nidofy/desktop-extras/src/storage.ts) grants managed capacity through the application-owned Windows helper. The canonical parent of an ordinary `DSH_HOME` is the distribution root; its Windows volume serial and file index identify the physical root. Sibling homes register in one ledger at `.nidofy-storage-v1/ledger.jsonl`. New home registration waits for existing grants to settle. An imported home at `imports/<operation>/harness` is the sole exception: it resolves the original root only after an explicit adopted record matches both directory identities. It cannot initialize a nested ledger or relocate the original ledger.

The [managed allowlist](src/quota.rs) includes connection documents, working notes, extras including pet resources, action/change records, artifact staging, snapshot scopes and snapshots, and retained SQLite index files. Official sessions, attachments, storage, runtime, project data, `.env` and credentials remain outside this managed budget. Unknown home/cache entries, links, inaccessible paths and unstable observations refuse reconciliation. The inventory endpoint is a separate read-only observation and never grants capacity.

## Format acknowledgement

The current native format uses [schema version 2](quota.schema.json). Each line is a lowercase SHA-256 digest, one space, the UTF-8 JSON record body, and LF. Owners, leases and imports are upserts keyed by epoch or operation identity; homes are a growing set. Scalars replace prior scalar values. Replay retains settled grants for lost-ACK inspection. The digest detects damage; it is not an authorization signature. Windows creation times are unsigned 64-bit integers and must not pass through JavaScript number parsing during replay.

Readers retain and replay the v1 prefix, then append v2 records without rewriting prior bytes. Old helpers refuse v2; downgrade requires the preserved pre-upgrade distribution copy. Unknown schemas, phases, complete malformed records, version regression or a physical root mismatch refuse access without resetting the ledger. An incomplete final line is uncommitted and is truncated under the exclusive lock. Each record is bounded to 4 MiB and the journal to 128 MiB; reaching either ceiling refuses new writes. There is no automatic compaction, deletion, relocation or rebind. Rust serialization tests check actual fields and phases against the schema. This file changes no Session header or event and creates no Session acknowledgement.

## Lock, commit and acknowledgement

The helper pins existing ancestors against rename/deletion and opens the ledger with Windows sharing disabled, rejecting reparse points and ledger hardlinks. The exclusive file handle serializes readers and writers across Hosts. Acquisition may refuse as busy; elapsed time never expires an owner. Each append uses write-through and `sync_all` before replying. A complete record surviving a lost ACK is synchronized before inspection. This is the ledger's sync receipt, not a new durability guarantee for Notebook atomic replacement or other consumer files. Tests do not establish physical power-loss, independent-SID or installer qualification.

Reserve accounts for measured bytes plus every unsettled ordinary and terminal grant. Available disk space must also cover grants, configured safety space and five maximum ledger records per unsettled operation. Each import journal append rechecks that margin plus its own complete record bytes. The caller creates the operation identity before sending. Lost ACK, helper failure, invalid output or settlement failure retains the charge; inspection returns reserved, settled or unknown and never authorizes replay. Reducing the managed limit prevents new grants without shrinking existing terminal capacity.

The authenticated storage page reads `status` without sweeping grants. `QuotaStatus.measuredBytes` is null for that read; `observedBytes` is the last ledger measurement, and ordinary and terminal reservations remain separate. Opening the client may register its owner and synchronize or repair an incomplete journal tail under the existing lock. Explicit `recover` can settle confirmed drained operations and rescan; incomplete scans retain charges. The page also reports journal use against its fixed ceiling. The separate inventory describes this home and imports, not an atomic distribution admission scan.

## Owner and native authority

Each random Host epoch is bound to an actual Windows process handle observation: PID, creation FILETIME and wait state. Access denial is unknown and blocks reclamation. A native mutation receives a private stdin capability containing the operation identity and a random token; only its hash persists. UI/model command JSON cannot select the wrapper or grant a budget. The helper checks home, command scope, available ordinary/terminal bytes and owner lifetime, records its own creation identity durably, then starts mutation. Raw mutating commands refuse before opening the snapshot store.

Every native file write checks the remaining grant; ordinary mutation checks owner lifetime again. A write already past that check may complete after owner exit, so its worker must drain before reclamation. Native end consumes the original begin grant's independent terminal allowance once. Unknown end results cannot replay that capability. New helper work requires a living Host; a worker already holding terminal authority can finish its terminal record after Host exit.

## Settlement and consumer limits

Product import uses one caller-retained identity for both the operation and its quota grant. Native admission binds a fresh staging directory to that physical root and identity; existing final/pending residue refuses replay. The explicit cumulative byte ceiling covers every copy, encoded successor and complete temporary metadata write; each debit is persisted before its writer starts. This is an enforced ceiling, not an estimate from source size. Product coordination uses the ledger lock without separate owner/takeover lock files. Windows Session write locks are kernel objects; verifier workers only read. File-byte limits exclude filesystem allocation overhead and decoded memory.

Import phases are copying, publishing, ready, interrupted and adopted. Publication first synchronizes the publishing intent with directory/home identities and the READY receipt digest, then renames within the same parent, then records ready. A lost ACK is inspected, never automatically replayed. Explicit recovery requires the original writer to have exited before completing a recorded publication from either matching pending or final directory. An interrupted copy stays preserved and cannot resume. Cancellation before publication drains the writer and marks interrupted; late cancellation cannot undo publication. READY describes a validated copy, not selected product state or power-loss durability.

Adoption is explicit and in place; it changes no patch absolute Session root and does not switch the running Host. It requires drained grants and matching directory/receipt identities. Existing excluded Session/attachment/profile bytes become a visible fixed retained charge; later official excluded growth follows normal home policy. The scan counts managed adopted-home files once and keeps the retained charge even if excluded files later disappear. This conservative charge has no release mechanism. Parent review/receipt files remain measured. Workspace trust and protection scopes are quarantined under review; credentials, plugins and schedules are not activated. The read-only inventory reports live lengths, not these ledger charges.

For an adopted Desktop data root, the sibling `electron` directory follows the ordinary runtime exclusion. Its locked Chromium state cannot block managed reconciliation. The scan still checks the recorded import/home identities and measures review, receipt and managed home files; the fixed retained charge is unchanged.

`import-review` reads only ready or adopted operations and pins the committed directory/home identities. It checks the complete READY receipt against the journal digest before returning its category report. Reports use schema version 1, at most 16 categories and 128 KiB; unsupported or oversized reports refuse. Older receipts without a report return null. This read changes no phase or charge. `import-inspect` remains a journal observation and does not validate current receipt bytes.

The imported home stores validated configuration in `cordis.patch.yml`, the Loader's home layer, so the application-owned Desktop profile receives the copied Session root and encoding. The returned home uses a DOS/UNC spelling for launch environment consumers; native identity checks retain the canonical path. HTTP import mutations refuse without the storage owner; only standalone library callers can choose local import behavior.

Node leases await their registered write jobs; native settlement waits for the actual child to close. Reconciliation returns without reclaiming if any owner with unfinished work or any recorded worker remains alive. Only a complete scan after all writers drain replaces measured bytes and settles grants. A failed scan retains finished grants. Physical file identities deduplicate hardlinks across registered homes and imports. Quota never deletes project files or replays an action.

The product wires Notebook publication/conversion, settings, connection transactions, ProjectActions, change review, artifact registry/staging, preferences, probes, diagnostic archives, paused schedules, pet imports/deletes and all native mutating commands. Notebook rejection now precedes crash-tail truncation; later settlement failure cannot reverse a selected Notebook. Read-only diagnostics remain reachable when admission fails. Standalone library compositions without this product owner retain their explicitly local behavior; they are not cross-Host quota participants.

The product uses the official SQLite provider with `path: ':memory:'`, including in-memory temporary tables. Old disk indexes remain counted and untouched. Cold search rebuilds and memory use are not bounded by disk quota. Product import requires explicit preview fingerprint, operation identity, write ceiling and confirmation. Existing standalone copies have no product authority and cannot be adopted through an invented operation record. Pet ZIP exports must target outside the distribution root. Cooperative writers must use the product owner; arbitrary external filesystem writers and concurrent malicious path replacement are outside this protocol's capacity guarantee.

Snapshot management uses the same native grants and existing per-file restoration checks. Archive verification returns a revision bound to the pinned physical directory and validated manifest. Import requires that revision as `expectedRevision` and rechecks before creating any snapshot bytes; a changed preview refuses with `PROTECTION_ARCHIVE_PREVIEW_CONFLICT`. Import stores a snapshot without restoring project files. Restoration requires a separate current preview, explicit file selection and confirmation. Cleanup returns a bounded read-only cache/staging candidate list; its change token grants no deletion authority, and no cleanup executor is available. Snapshot and journal formats are unchanged by these management APIs.
